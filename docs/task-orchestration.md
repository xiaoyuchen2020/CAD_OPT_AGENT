# 可恢复的复杂 CAD 任务（MVP）

范围：在现有自定义 Harness 和共享 CAD 工具层上增加任务记录；不接入 AR 策略、任意代码执行或新的付费模型路径。默认运行时选择不变。订阅验证使用 `responses_subscription` / `siwc_sol`，明确关闭回退。

## 任务与工具契约

`cad_agent/analysis/tasks.py` 管理 `agent_task` 持久记录。每个任务绑定 `snapshot_id`、源 DXF SHA-256、原始问题、修订号、执行记录 ID、子任务、批次、证据、工具观测与交付检查。子任务记录原始要求、能力、依赖、验收说明、状态、调用次数和对应的证据/批次。

自然语言先按句子与明确连接词生成最多八项要求（超出时合并尾部，不丢弃文字）。复杂问题先调用 `plan_task`：模型逐项选择能力和依赖，服务端验证无遗漏、重复、外部依赖或循环。模型不能通过计划修改完成状态或生成证据。没有标点的复杂长句可能仍被视为一项，这是本阶段的明确限制。

能力类型为 `scope / enumerate / measure / lookup / compare / highlight`，不按具体项目或楼层分支。已有工具接口保持业务参数不变，复杂任务调用增加 `task_ids`。批量枚举、测量、高亮可一次关联多个要求。既有简单房间问题仍可使用确定性预执行路径。

状态：`pending`、`running`、`completed`、`partial`、`waiting_input`、`blocked_capability`。`completed` 表示该项已有交付记录，不表示候选空间或建筑语义已被确认。

## 停止与恢复

- 批量工具返回不再直接结束整个任务。单位未知只将关联测量置为等待确认；其他独立查阅继续。
- 每项至多五次工具调用，连续重复调用限制只阻塞相应分项。已有总 Token、时间和工具预算仍生效，不能依靠拆分无限调用。
- 最终答案逐项对应原始要求；批次表已经交付的枚举/测量/高亮可不由模型重复抄写。未交付的要求必须补结论或明确缺口。来源引用、推导和测量状态仍由原有校验处理。
- 批次验收检查行数、重复候选、每项证据与高亮，单位未知时禁止生成面积数值。分页仅在同一范围和名称的完整候选集合覆盖后才算枚举完成；测量和高亮仍分别检查。
- 单位确认只运行本地几何计算，不隐式调用模型，也不修改图纸原始单位。重复同单位确认幂等；不同单位不能覆盖旧确认。
- 新测量替换旧批次，过期批次观测不能支撑新回答；依赖测量的综合结论重新等待执行，独立原文读取保留。旧模型答案作为历史记录不自动改写。
- 恢复模型分析需显式点击“继续未完成分析”，复用保存证据与计划。服务重启保留中间结果，并将中断执行改为可继续状态。

## HTTP 和网页

- `GET /api/drawings/{snapshot_id}/tasks`：最近十条任务。
- `GET /api/tasks/{task_id}`：公开任务状态、子任务与批次引用。
- `GET /api/tasks/{task_id}/evidence/{evidence_id}`：已读取原文证据。
- `POST /api/tasks/{task_id}/confirm-unit`：`{batch_id, unit, confirmed:true}`。
- `POST /api/tasks/{task_id}/room-batches/continue`：`{batch_id, offset}` 分页或 `{batch_id, frame_id}` 确认候选范围，二选一；不调用模型。
- `POST /api/chat-runs`：沿用原请求参数，增加 `resume_task_id`；图纸和问题必须与原任务一致。

运行中的任务不接受并发恢复或单位修改。跨图纸、不同源版本、外来批次和非法范围均拒绝。网页显示逐项进度、批次结果和待确认项；重新打开图纸可以读取已保存任务，不重新推理。

## 验证与边界

本地测试覆盖自然语言拆分、非法计划、批量等待不阻断查阅、漏项拒绝、单位幂等确认、依赖失效、已有证据恢复、分页覆盖、范围确认、重启恢复和重复检索隔离。合成图单位确认测得 24 m²；不能将该结果当作真实工程图测量准确性证明。

真实验证计划和结果位于 `artifacts/task-orchestration-20261016/`。只验证两个固定问题，每题一次产品提交；订阅工具循环可能包含多次模型请求和一次受限答案纠错。原始 DXF 单位未知，未替用户确认单位。交付检查主要保证结构完整和可追溯，不能独立证明模型的语义解释、空间身份和工程判断正确。
