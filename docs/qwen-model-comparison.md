# Qwen 与 DeepSeek 的 Harness 对照（2026-10-14）

结论：模型选择已接通，当前仍建议默认使用 DeepSeek + 原生运行时。Qwen 大模型在本轮复杂工具调用中不稳定；中、小服务尚未开启自动工具调用，无法完成本产品的工具问答。

累计 token 包含服务已报告的失败尝试；“—”表示没有成功回答或服务未报告 usage，不是零消耗。中、小模型每种 Harness 都有 12 次 HTTP 拒绝，没有 usage。它们约 0.1–1.3 秒的拒绝耗时不能算问答速度。不同模型 tokenizer、缓存及服务计费不同，token 不直接等于费用。

## 失败诊断与样例

- Qwen 中、小：共 72 次均为 `MODEL_TOOLS_UNSUPPORTED`。三个 Harness 结果一致，问题位于远端服务的工具调用配置。本次没有修改远端服务。小模型的 2K 总上下文还需另行解决，当前完整工具定义和输出预算无法直接套用。
- Qwen 大：36 次中 27 次没有完成有效工具调用。候选中可见正文里的伪 XML / function_call 文本，以及带多余引号的工具名；没有把这些文本转换成可执行调用。9 次完成过工具，其中 3 次发布答案。33 次失败中 31 次为答案校验失败，2 次被工具白名单拦截。可能涉及模型对工具格式的遵循与服务模板/解析器匹配，本轮不能单独归因为模型能力或 Harness 本身。
- DeepSeek：29/36 发布，7 次被答案引用/数值校验拦截，包含文件名中的数字被当成原图事实、章节编号没有对应来源、邻近数字不属于所引条款等。

## 开发建议

保留 DeepSeek + 原生作为默认；Qwen 配置作为试验选项。先修复中、小服务的工具调用开关与匹配解析器，并确认上下文预算；对大模型先用小规模工具契约样例验证标准 tool_calls，再重跑本套题。不要先增加轮数，也不要把任意文本调用表达式当作工具执行。

若要继续比较效率，先补强“目标条款确实读到”和“每条结论引用语义匹配”的验收，再只在共同完成且质量合格的题目上比较耗时与用量。本轮未改变默认模型，未加入 AR024 策略，未开放一次性代码执行。

110 项完整测试通过；新增模型配置、会话配置隔离、回退保留模型、模型桥接、错误脱敏与统计口径的 7 项测试也独立通过。配置、API 与复跑命令见 [Qwen 接入说明](qwen-models.md)。
