# 具体缺口的有限恢复

`analysis/gap_routing.py` 在现有任务台账上记录恢复建议，不执行工具，不建立第二套调度，不改变验收条件。

- 成功结果由 `TaskFocus.record` 调用 `record_result(session, name, task_ids, result)`；工具失败分支也可调用该接口，传入包含 `error` 的结果。当前 trace 的参数用于绑定实际尝试。
- `task.data.gap_recovery` 持久保存缺口来源、推荐历史、尝试与解决凭据。`context(data)` 返回最多 24 条只读摘要；完整台账最多 64 条。超过上限不增加恢复记录，原始工具诊断仍保留。
- `schedule()` 给已有待办附加 `recovery_actions`；不新增强制待办、不修改原来的 `next_action`。`TaskFocus` 按当前运行时能力开放建议工具，并把摘要送入模型上下文。工具调用与返回的最后一组消息保持配对。
- 工具建议通过注册 schema 校验。缺参数时明确返回 `arguments_required` 与 `required_parameters`，不猜来源编号、坐标、单位或操作数。所有建议均要求模型显式调用，`automatic_replay=false`。

| 观察到的缺口 | 优先补查 | 解决条件 |
| --- | --- | --- |
| 表头未读/未定位 | 已知表的原生语义读取 | 同表返回实际表头行及原文证据；仍不证明适用关系 |
| 单位缺失/冲突 | 同来源文字、同表表头或原生尺寸；已有批次沿用单位解析器 | 同单元格返回明确单位原文，或批次解析器确实返回 resolved；不自动作用户确认 |
| 空间对象身份未明 | 已绑定实体的原生几何，再用同来源范围局部出图 | 调用成功及视觉绑定均不自动确认工程身份，未证实仍保留 |
| 开口双侧连接未建立 | 同组件关系记录，再局部出图 | 同一开口返回双侧门连接支持；其他开口不抵消缺口 |
| 计算缺操作数 | 复用已有 calculation_inputs 的完整建议，补齐后重算 | 同计算键、实际已计算且对象绑定成立 |
| 连续没有新证据 | 已命中且未读的来源 | 新增真实来源证据；没有入口则停止，不生成换词检索 |

恢复最多记录 3 次不同实际尝试。等价默认参数规范化后识别重复调用，已经尝试的同参数动作不再次推荐。推荐会检查已有任务依赖、子任务额度、全局额度、探索停止原因及实际 runtime/provider；没有可用路线、参数来源或视觉通道时保留具体停止原因。预算消耗仍由原工具执行器管理，建议和解决记录都不授予交付或覆盖完成。

跨图门表的表头或单位缺口保留目标 `snapshot_id`，通过 `read_door_schedule_table` 继续读取；其他快照的同名表不能关闭此缺口。任务界面的“查看待补项与恢复状态”读取 `GET /api/tasks/{task_id}/gap-recovery`，只展示既有审计摘要，不启动模型或工具。

局限：规则只读取受支持的结构化诊断，不从原文关键词推断任意新缺口；视觉语义仍由实际看图与已有交付校验负责。此模块没有真实模型 E2E 验收，也不新增模型、通道或付费回退。
