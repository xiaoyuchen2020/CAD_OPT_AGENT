# 通用几何能力三阶段实施与 AR009 重试记录

三个阶段的首轮实现和实图 API 重试均已完成，代码已合入当前开发目录的工作区，未提交或推送 Git。结果支持继续产品化局部几何计算与证据管理，但 **AR009 仍未达到所有对象、全路线最不利净宽的完整识别验收**。

## 实验口径与可复现性

- 同一 DXF、同一 AR009 规则摘录、API `gpt-6.1-sol`、`high` 推理；输入原文件只读，生成代码仅允许在无网络 Docker 中运行。
- 三阶段均未设置任务 token、轮次、工具调用或总耗时上限。页面大小、几何类型前提、来源与执行隔离仍有约束；服务端限制不受本实验控制。
- stage1/stage2 关闭答案交付门禁；stage3 对结构化几何声明启用 `enforce`，仍不运行产品的整套最终答案门禁。自由文本报告需要人工复核。
- 运行器调用生产 `CadAgentSession.execute` 与同一注册工具，并显式发送图像；它是监督 API 适配器，不能等同于默认 UI/订阅端到端验收。生成代码能力没有默认开放到所有产品通道。
- 原有默认模型通道与日常预算保持不变。实验关闭了既有通用上下文编码器以保持本系列口径；第三阶段另启用新增几何页面投影。因此实验用量不能直接代表产品默认配置。
- 每阶段保存 `code-snapshot`、代码哈希、模型请求/响应、工具回执、图片、人工引导及产物。早期重启、代码演进及监督收束均保留，不能当成严格单变量 A/B。

## 第一阶段：局部计算闭环

交付不可变源几何包、原生路径查回、有限直线法向间距、同心弧有效角域径向间距和带测线的源图渲染。结果携带来源哈希、单位、有效域、算法版本、测线与未确认条件。

真实试验得到4个有效局部值，另有1个不适用配对。独立原生 DXF 复算4/4数值一致，但出现了实体ID编造、将另一对象线段归为1#、同墙双面以及图像后提前结束。先后补充了范围读取、图像消息角色、SDK导入和结果交付指导。第一阶段以监督者明确要求保存局部成果的阶段检查点收束，并非自主完成全部任务。

因此第二阶段重点从“能否计算”转向“如何选择候选并追踪对象”。没有将原实验人工给出的五对边界写入算法或提示词。

## 第二阶段：图示、候选与分段调查

新增标题候选检查、对象假设、边界配对发现、选定线/弧分段采样、障碍顶点事件细化及源回执导出。尺寸锚点排序使用源端点残差和共同有效区间，不按规则期待宽度排序。

真实试验完成13个局部值、8次分段采样调用、9次图像渲染和4次导出。13/13局部值独立复算一致，但选边仍明显不可靠：局部测线涉及轴网、墙带或其他图元；1#与2#没有可靠拆分；4次对象假设登记错误地把文字来源ID放入几何实体字段。一次引导要求核对测线和精确ID，未提供正确边界。

原生 `COLUMN` 类型与柱的工程角色被模型混淆，也说明空查询不能当成不存在障碍。第三阶段据此增加原生类型提示、测线局部放大、ID/标签错误反馈和跨图示复用提醒。

## 第三阶段：逐项检查、状态与性能

实图重试得到7个有效局部值，2个不适用配对；1次请求使用了错误bundle ID。模型自行选中了原实验人工审查过的 `13AFB/13B32`、`140AF/140AB` 两对圆弧，均约7100原图单位。本轮提示词和人工引导未提供这些句柄或期待宽度；此对应关系只由监督者在事后审计中比较，不能推广为完整路线识别成功。

模型随后记录了分段采样和候选柱的条件影响，并实际调用结构化声明校验与结果导出。人工引导共2条：解除固定文件名导致的重复JSON拼装，以及指出跨平面/顶板/剖面重复绑定同组源线的问题。最终报告将不成立的图示归属降为标签候选与未绑定几何，不把局部或采样最小值说成全程最小净宽。

本阶段增加：

- `validate_geometry_claims`：来源引用、局部数值、单位、采样范围逐项检查。`shadow`保留提醒，`enforce`拒绝该项不支持的结构化声明；有效局部结果与探索过程保留。
- 正式交付链增加局部/全程表述检查；这是窄范围启发式，不能理解并验证任意自然语言，也没有自动确认工程身份的能力。
- `read_geometry_workset`、假设`supersedes`、失败记录和部分操作回执。局部成功不授予完整问题完成状态。
- 几何页无损表格投影；完全相同的重复页只引用同一请求内已完整出现的定义。保留分页、缺项、冲突和来源差异。本轮没有出现重复页去重命中；单轮表格投影最多减少69270字符，不能把字符数当token节省。
- 直接下载不可变JSON产物，源文件变更时拒绝继续测量；旧算法产物仍可按原版本下载和审查。

运行中还发现现有 `get_drawing_context` 对四个图框重复重建相同布局。实测原调用约145、141、75、61秒。补充布局分析缓存后，用同一实图回放四个查询：首个约65.32秒，后续约0.52、0.53、0.53秒；`frames/subframes/diagnostics/coverage` 与原回执逐字段相同。该性能修复是独立本地回放，不计入第三阶段 API 运行的时间收益；首次构建仍较慢。

## 正式调用链发现与修复

监督适配器直接调用工具执行，因此另用正式 `invoke_tool` 链验证生产集成，发现并修复：

1. 假设结果的`source_binding`字符串不符合任务进度模块所需的对象契约，改为明确的来源检查状态对象。
2. 路线结果含有`hypothesis_id`引用，早期工作集误将路线回执覆盖到假设摘要中。改为按工具拥有的记录类型保存，并可从不可变假设记录恢复早期摘要。
3. 外层工具缓存可能在重复调用时跳过源文件哈希复核。将工作台工具纳入每次来源复核，内部不可变结果仍可复用；实时状态读取也不再复用过期摘要。
4. 跨图示复用同组几何仅作可解释提醒，不一律禁止合法的共享证据；旧假设被显式替代后退出当前冲突清单。

这些修复没有改写三次实验的原始轨迹。最终版本在独立复制的实图工作区，复放第三阶段全部7个成功局部值的正式调用链：数值不变、假设保留、7项局部声明支持；人为加入的7项错误物理单位和7项无依据全程声明被逐项拒绝。同时逐项调用正式最终答案校验：7份保留未知条件的局部回答获准交付，14份添加错误单位或全程结论的回答被拒绝。此回放不调用模型，也不是新增自主识别成绩。

## 工具、提示词、校验器的落点

| 落点 | 已实现职责 | 仍然保留的边界 |
| --- | --- | --- |
| 源与几何工具 | 几何包、精确路径、LINE/ARC局部运算、候选、分段采样、条件障碍影响、图片与产物 | 不通过数值接近规范阈值确认所选面；当前不支持所有曲线和多段线拆分 |
| 提示词 | 先看图、区分图示、核对尺寸方向/端点和测线、先局部再调查缺口、复用回执 | 无样本句柄、坐标、图层白名单或固定对象数量；不能替代可靠的语义识别 |
| 校验器 | 数值/单位/声明范围逐项限定，跨图示共享提醒 | 不自动判定坡道类型优化、完成面、同高度或全路线覆盖 |
| 状态与配置 | 引用和记录所有权分离、假设修订、来源复核、无损投影、布局缓存、独立校验和代码执行选项 | 无新增默认付费回退；未根据单张开发图纸下调日常预算 |

## 测试证据与未解决问题

- 扩展全量回归：2128通过、101跳过，50项因隔离目录缺少历史冻结输入失败。将这50项放到具备原输入的主开发目录复跑，50/50通过。不能将前一次日志写成“全量一次全绿”。
- 主开发目录集成回归160项通过；最后补充假设身份及正式答案门禁后，相关33项再次通过。两组有重叠，不相加。
- 新几何/状态/跨图示/缓存专项：最终39项通过；包含平移旋转缩放、不重叠、跨零度弧、非有限数、窄障碍、来源变更、缓存复核、旧工作集恢复与正式工具链。
- 上下文编码与读取相关测试71项通过；额外空间交付检查33项通过；上下文组件测试11项通过。各组存在重叠，不相加成独立总数。
- 真实源局部数值独立核对：stage1为4/4，stage2为13/13，stage3为7/7。它们证明数值复算一致，不证明边界工程含义。
- 相同已保存结果的shadow/enforce检查回放，以及上述7条正式链实图回放分别存档。没有进行新的单变量API校验模式A/B，也没有进行降低预算的实图A/B。

后续优先级根据本轮结果调整为：

1. **图示与边界归属**：建立有证据的图示局部范围、分离几何与标签归属；防止把轴网、同墙两面、符号或相邻对象配成通行两侧。仅增加unknown字段无法完成识别。
2. **连通路线与过渡**：从已选局部边界追踪直段/曲段两端，处理断线、分叉、过渡及多段线；独立建立路线全集和覆盖分母。当前采样没有端点/过渡极值证明。
3. **物理口径与高度**：确认原图单位、结构/完成面，以及障碍与通行面的高度关系。当前所选障碍若同高的投影影响只是假设结果，不能宣称无障碍或完整净宽。
4. **工具返回体积和初次解析**：已有尺寸工具一次仍返回较大数据；新增投影没有覆盖所有旧工具。先保持证据不丢失，再优化初次布局构建和大尺寸页。
5. **跨图纸验证与预算对照**：另取未参与本轮引导的图纸，固定金标准后测试对象归属、选边与覆盖；再固定工具/提示/模型进行校验模式和预算对照。本次只有一张开发图纸，不能证明泛化。
