## 本次交付

- DeepSeek 官方 API，`deepseek-flash`（DeepSeek-V4.1-Flash），显式非思考模式的 Chat Completions 工具调用。
- 六个通用工具：图纸概览、原文检索、上下文读取、砌体抽取、事实查询、证据读取。
- 后台问答任务、真实工具执行进度、限次循环、失败状态、token/耗时记录、同图纸追问。
- 后端校验模型答案 JSON、已读取证据、当前 snapshot 和数值来源；原图坐标始终由已有来源映射生成。
- 模型答案单独保存，不覆盖已有事实集合；本地事实查询和手动提取保留。

密钥放在仓库根目录 `.env` 的 `DEEPSEEK_API_KEY=` 后。配置存在不等于调用成功；本次已使用本机配置完成真实调用。密钥不在报告、前端、Git 文件或模型输入中。编辑后需重启服务。

## 验证中修正的问题

1. 原始上下文只给“邻近”关系，模型可能把前一章节最后一条误归到下一标题。工具现返回阅读顺序、前后关系、每段自身的解析上下文 ID，并为标题提供已有结构关联的子条款。
2. 大图的 skipped/unresolved 列表会撑大模型工具返回。模型只接收覆盖计数和有限诊断，完整列表仍留在事实 API。
3. 模型有时引用正确原文却把工具运行统计混入图纸结论，或在同一句比较中漏引另一章节。服务端指出具体结论、缺少依据的数值及可核对的已读证据，允许一次纠正。
4. 最后一轮才发现引用问题时原先没有纠正机会。现为最多8轮交互，最后一轮保留给答案整理，加最多1轮仅用于最终答案修正；仍最多16次工具调用和180秒预算。达到上限显式失败，不发布未经校验的答案。
5. 提示词明确区分B密度等级、A/MU块材强度等级与M类砂浆等级。

首轮真实结果及中途预算失败保留在报告目录。最终成功不代表每次重跑都稳定成功；模型响应仍具有随机性。

## MVP 的保留限制

原文检索是子串匹配；表格结构不完整时可返回不确定。引用校验证明出处存在，不证明所有语义、章节关联或额外解释正确。模型回答可能冗长，仍需要人工核查。字体和证据框为实体/区域估算，不能替代原生 CAD 精确渲染。当前不进行工程量计算、图纸合规判断、优化策略、跨图纸分析或自动修改解析代码。

网页追问的主问题和来源已核对；仍观察到模型将“虚线示意的隔墙由用户装修自理”进一步解释为“本次砌筑范围外”。原文没有直接定义合同施工范围，这类额外解释尚不能作为已确认事实，需人工复核。来源验证无法替代这一语义判断，本轮不为此扩展施工范围规则。
