# 复杂表格搜索、读取与来源验证

2026-10-26；契约版本 `table-document-v1.0.0`。

本次把表格建成独立、可分页、可追溯的文档。旧的文字段落和语义组件仍可检索；复杂表格不再要求先被旧组件识别，才能恢复结构。实现仅整理图纸事实，不作合规或优化结论。

## 六部分实现

| 部分 | 实现位置 | 行为 |
| --- | --- | --- |
| 多源发现 | `tables/topology.py`、`native.py`、`candidates.py`，`cad/reader.py` | 读取 ACAD_TABLE 元数据及块图形；按布局、块实例、局部旋转恢复原生线框；无框对齐文字生成候选；局部视觉复核入口独立于旧表格 ID。 |
| 结构恢复 | `tables/binding.py`、`contracts.py` | 原始行列、合并跨度、重复分组、内部子表、表头路径、行对象、备注分别保存。字段关系和文字读取状态独立。 |
| 精确来源 | `tables/binding.py`、`validation.py`，`evidence.py` | 单元格绑定实体、原文、字符区间和边界；字段保留标签、值、单位来源。保留 CAD 转义原文，同时提供解码显示。 |

## 工具与典型流程

1. `search_tables(query, level, layout_id, frame_id, bbox)` 返回有界匹配及候选，不用整表大文本充当搜索结果。
2. `inspect_table(table_id, view)` 检查结构、诊断或覆盖范围。
3. `read_table_content(table_id, node_id, fields, limit, read_plan_id, cursor)` 按表、节点或字段读取。首次不传计划和游标，后续使用原样返回值。
4. `recover_table_region(candidate_id | layout_id+bbox, method)` 在局部范围重新恢复几何或准备视觉复核。
5. `review_table_region(recovery_id, cells)` 只接受已实际交付图像的视觉复核；检查边界、重叠、实体归属。纯视觉转录保持候选，不升级为原生事实。

工具已注册到现有 agent、证据账本和任务归属校验。明确的“这张图中的〈表名〉内有哪些内容”通过 `table_documents` 流程逐页读取，订阅模型逐格登记 read/uncertain，服务端按照原始行列和来源编译完整交付。模型不能省略或重复单元格；无效复核最多修复一次。条件查询、歧义表名、关联图纸和显式通用 agent 模式继续由通用工具流程处理。

阅读计划绑定任务所有者、快照、源签名和选择范围。重复读取同页不会重复增加覆盖率；游标不能跨任务、换版本或更换字段集合使用。未完成任务可以根据持久化的计划及观察记录恢复；恢复仍受当前执行预算限制，不承诺无限续读。

## 来源与不确定性

- `source_state`：原始文字是否有可追溯来源。
- `structure_state`：单元格边界是否得到原生几何支持。
- `binding_state`：字段、表头、单位及分组归属是否得到支持。
- `selection_complete`：当前选择中的单元格是否全部交付。
- `table_read_complete`：整表被选择、全部单元格交付、无未归属文字且结构有来源支持。
- `scope_exhaustive` 保持 false：整表读完不等于整张图纸所有内容都已被解析。

数值引用必须回到完整原生实体。旧段落中的 `1933平方米` 可能来自序号 `1` 与面积 `933` 两个实体，本次修复允许完整实体 `933` 独立引用；禁止任意切片制造 `33`。新表格始终分开保存序号与数值。

文字插入点略微超出外边框时，在横向 0.15 倍字高内保留为边缘来源，单元格归属标为候选，并在界面提示。不会将邻近的外部文字自动确认为字段。说明文字有来源、字段关系待确认可以同时成立。

历史结果通过冻结文档展示，并核验源文件哈希和原文区间；历史文档可查看，但旧游标不能继续读取新版本。没有把历史结果静默替换为新解析结果。

## 有界运行与兼容

- 当前单次发现上限：30,000 条相关线段、256 个候选、每表 4,000 个单元格；触顶产生诊断。
- 单页最多 64 格；整表工作流请求 24 格，实际页还受模型上下文预算约束。
- 来源读取额度不取消全局调用、模型轮次和时间限制。预算不足保留任务与已读记录，不伪造完整状态。
- 保留自建订阅 harness；不自动退回付费 API。`source_read_batching` 仍默认关闭。
- 原生解析器版本更新为 `native-dxf-v5.2-native-tables`。旧快照可利用已有几何建立新表格文档；需要新 ACAD_TABLE 元数据时重新解析会生成新快照。
- 非平面表格、不受支持的代理实体、未解析外部图像、断线和含糊无框结构仍可能仅得到候选或诊断。纯图像表格可经视觉入口复核，尚未经过本次三张原生图纸同等级的真实验收。
- 本次不新增通用 OCR 服务，也不保证任意未来表格自动准确。可靠性来自保留证据、覆盖核验与显式待核状态。

## HTTP 与界面

前缀 `/api/drawings/{snapshot_id}/table-documents`，提供 `POST /search`、`GET /{table_id}`、`POST /read`、`GET /{table_id}/cells/{cell_id}` 和 `GET /{table_id}/overlay.svg`。

回答中的表格视图按分组展示行列和跨度，逐格提供“定位原图”。点击返回单元格边界、原始实体及局部叠加预览，不以整段文字框代替目标单元格。空白保留为空，边缘来源与候选关系显示待核。

## 验收方式

合成回归覆盖旋转实例、原生 ACAD_TABLE、无框候选、分页恢复、跨任务伪造、来源变更、来源清单漏项、字符边界、单位/备注、视觉交付门控、边缘文字、历史版本和前端合并单元格。

真实验收使用 `scripts/validate_complex_tables_real.py`。源数据复制到隔离目录，不修改生产记录。`--fire-gold` 核验独立人工读图预期；`--reference` 使用独立来源引用清单。默认只进行本地核验；`--live --publish --account-data ...` 才使用现有订阅执行实际后台问答和发布流程。模型验收必须同时满足来源覆盖、实际模型调用及任务 completed。

本次具体验收结果见 [验收记录](complex-table-validation-20261026.md)。
