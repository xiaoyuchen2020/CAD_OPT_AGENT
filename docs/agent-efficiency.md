# Agent 探索与上下文优化（2026-10-15）

> 2026-10-23 更新：v2 将有效进展绑定到要求，做法查阅使用专门提示、工具目录与预算。下文为历次机制说明，当前预算和回退范围以 [v2 实现](cad-agent-execution-v2.md) 为准。

## 独立来源批量读取开关（2026-10-19）

`ChatRequest.source_read_batching` 默认 `false`。网页的“问答设置 → 高级选项 → 批量读取来源”可手动开启，作用于后续问答；刷新页面恢复关闭。API 调用方可显式传入 `"source_read_batching": true`。

关闭时不提供 `batch_read_sources` 工具及其提示词建议，模型请求扩展工具也不能自行开启；直接调用会返回 `SOURCE_READ_BATCHING_DISABLED`，不会执行任何子读取。原有 `read_source_context` / `read_assembly` 逐项读取、分页、证据校验、受控并发及其他探索策略保持原设置。开启后继续使用原有批量额度、失败隔离和分页规则。

这是独立开关，不需要切换整个 `agent_policy`。已运行的历史测试保持原样。2026-10-19 修复后已完成批量读取关闭状态下的三档模型各 20 道 B 题真实测试，证据见 `artifacts/designer-facts-model-matrix-20261019`；该轮不是开关消融实验，不能将结果变化单独归因于关闭批量读取。

## 同预算订阅模型比较（2026-10-19）

`responses_subscription` 支持三个服务端固定档位：`siwc_sol` 对应 GPT-6.1 Sol low，`siwc_sol_high` 对应 GPT-6.1 Sol high，`siwc_luna_high` 对应 GPT-6 Luna high。请求仍通过 `model_profile` 选择，模型与推理档位写入逐轮诊断；不从请求接受任意模型名称或端点。默认档位不变。

`scripts/run_controlled_batch.py` 可在冻结计划的每题中指定这三个档位，并校验模型、推理档位和批量开关一致。每个尝试独立保存上下文、图纸记录、预算及终态；全题重试必须显式指定，原尝试保留。多档比较需要分别报告发布率、完整完成率、适用维度评分、全体/共同发布题耗时和未知用量；不能用任务调度完成代替业务完成。

## 实现与回退

默认 `ChatRequest.agent_policy="efficient"`，可在同一问答 API 请求中设置 `"agent_policy":"legacy"` 恢复旧提示词、完整工具返回及旧轮数控制。检索方式 `retrieval_mode` 与此开关独立；默认关键词检索未变。九个工具、三个运行时、来源数据和原图定位接口保留，不加入 AR024 策略或代码执行。

```json
{"snapshot_id":"当前快照ID","question":"内墙采用什么材料？","mode":"agent","runtime":"native","retrieval_mode":"hybrid","agent_policy":"legacy"}
```

主要修改：

- `analysis/efficiency.py`：单次问答内按校验后的完整参数复用工具结果。范围、分页和字符起点不同的调用不会合并；不同检索词也不会被当成同一查询。重新抽取事实后清空缓存。重复调用仍消耗探索次数。
- `analysis/session.py`：具体问题直接检索，不强制先浏览图名或抽取事实。默认候选由 8 个减到 5 个，仍可显式请求更多。只在模型工具调用边界精简数据，直接原文 API 保持原样。
- 原文阅读：目标每页最多 2,000 字符，关联区域最多 600 字符；保留精确 `text_span`、`next_start` 和截断标记。保留解析器父标题和请求的相邻区域，取消自动附带同级兄弟条款。长原文可继续分页。
- 模型侧删除重复的 `text/quote`、证据实体列表和检索排名诊断；完整证据、实体、位置仍保存在服务端，用于原图定位和回答校验。重复证据只返回 `already_read` 与 ID，前面的工具消息仍保留原文，不做有损的历史摘要。
- 提示词明确：取得对象、属性值和必要范围后立即回答，只为具体缺口补查。检索三次后提示收束；连续三次没有新增候选或证据时强制整理答案。工具累计返回约 28,000 字符后也收束（以完成一次工具调用为边界，可能略超）。这些是预算条件，不是语义充分性判定。
- 默认最多 6 个常规模型轮次，最后一轮留给回答，另留一次必要的格式/引用修复。答案校验失败后仅允许修正答案，不再重新开启探索。已有配置中的更小轮数仍优先。
- 原生与两个 Harness 共用上述工具策略和停止条件。最终数值/证据/快照校验没有放宽。

结果增加 `agent_policy`、`efficiency`；trace 中包含是否复用、响应字符量、停滞次数。`efficiency.model_requests` 记录各轮消息字符数，真实 Token 仍以服务端 usage 为准。
