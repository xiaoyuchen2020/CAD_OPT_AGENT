# 几何底座与房间净边界试点

实现位于 `cad_agent/geometry/`，仅依赖当前工作台、ezdxf 和 Shapely。参考 AR030 的成对墙面、门垛支持、室内种子点和显式拒绝诊断思想，独立实现；没有复制其房间类型、面积阈值、优化建议、平台查询或规则入口，没有运行时依赖 cad_llms_group。

## 使用

重启当前本地服务加载新接口；已有图纸无需重新导入。首次调用几何工具会从保存的原始 DXF 生成独立的 `geometry.json`，不改写原文、事实、图框、预览或源文件。

- 网页点击“测量房间”，在房间内部单击；拖动仍用于平移。选择点应避开墙体、柱子、设备及文字框。
- 或在“原文检索”点击房间名称，再点击“以此房间名称测量净面积”。多实体合并文字区域需改用明确室内点。
- 单位未知时需手动选择本次测量单位；记录 `unit_basis=request_override` 和 `applied_unit`。这不是对原 DXF 的修改，也不是程序已验证单位正确。
- “测量记录”支持原图叠加、局部 SVG 和证据 JSON。绿色为候选边界，橙色虚线为推断闭合，红色为内部未分类闭合轮廓。
- Agent 可从检索结果的 `region_id` 调用 `measure_room`。自由检索仍受模型行为影响；选定房间名称或指定室内点能减少范围歧义。

## 组件与接口

| 组件 | 职责 |
| --- | --- |
| `source.py` | 复用图元实例路径及 ID；原始参数、独立计算折线、单位、块变换后的坐标；STRtree 空间查询；最多缓存两个快照 |
| `rooms.py` | 在局部米制坐标下寻找成对墙面、证据支持的门洞闭合和种子点围合区域，逐边核对外侧支持 |
| `service.py` | 距离/长度/面积，房间测量，快照绑定与持久化，有限工具响应和完整证据，SVG |
| `contracts.py` | HTTP 与模型工具共用的有界输入契约 |

| Agent 工具 | HTTP |
| --- | --- |
| `read_geometry` | `POST /api/drawings/{sid}/geometry/read` |
| `query_spatial` | `POST /api/drawings/{sid}/geometry/query` |
| `measure_geometry` | `POST /api/drawings/{sid}/geometry/measure` |
| `measure_room` | `POST /api/drawings/{sid}/rooms/measure` |
| `get_measurement_evidence` | `GET /api/drawings/{sid}/measurements/{mid}` |

另外提供测量列表 `GET /api/drawings/{sid}/measurements` 和 `/measurements/{mid}/preview.svg`。输入的实体、文字区域、布局和测量 ID 均检查所属快照，禁止跨布局测量。

示例请求（替换为本图纸实际 ID，坐标为原始 WCS）：

```json
{"region_id":"region_..."}
```

或：

```json
{"layout_id":"layout_...","seed":[1000,1000],"radius_m":15}
```

未知单位需要显式 `unit_override`。`other_room_region_ids` 可作为不允许包含的其他房间锚点；`void_entity_ids` 仅用于已明确确认应扣除的闭合直线轮廓，自动模式不猜测设备/柱/洞口身份。

## 测量口径

- 原始参数覆盖线段、多段线 bulge、圆/圆弧、椭圆、样条和原生尺寸标注。HATCH 保留由边界路径生成的计算折线，尚不解释墙体语义。原生尺寸标注保留实际值与文字覆盖，但不自动关联构件或确认尺寸样式单位。
- 曲线计算折线使用 1 mm 弦差（源单位未知时为 1 图纸单位，物理精度未知；显式测量单位参与局部重新细分）。`query_spatial` 使用实际折线，不以包围框相交冒充线形相交；曲线近容差关系仍是近似。
- 基础面积工具只接受一个有效闭合轮廓，计算的几何面积不能直接称为房间净面积。长度/距离与曲线面积可能为细分近似。
- 房间试点只处理直线墙面。完整线网和成对墙面分别构造候选，不用外包矩形填补缺失边界。旋转及凹多边形同样在局部米制坐标计算。
- 默认墙面间距识别范围 0.06–0.5 m，默认支持率 90%，属于几何识别假设，不是工程优化规则。文字框的两圈边线也可能符合该假设，因此 `identity_status` 始终为候选。
- 门洞需同向墙面上匹配的缺口，且两端有实测横向门垛连接。默认最大闭合 3 m，可关闭。合成段、支持实体和长度写入证据；几何缺口本身不证明设计语义上是门。
- 闭合内部对象不自动扣除；未确认的内部曲线也会导致待复核。显式确认的内部闭合轮廓可按并集扣除，保留洞环。
- `measured` 表示当前几何假设下有唯一支持边界且无列明的阻断诊断；不表示工程验收。只有该状态返回 `area_m2`。`needs_review` 只返回 `candidate_area_m2`；`unresolved` 不产生确定面积。

## 证据与边界

记录包含源文件 SHA-256、快照、算法版本、请求参数、单位依据、室内点、外边界及洞环、逐边支持率、来源实体、推断闭合、候选及诊断。结果 ID 根据输入及版本生成；重复请求返回同一记录。数值量化面积误差估计不包含对象识别或单位错误。

模型引用测量使用 `tool_observation`，与原文引用分开。完整测量标为 `derived`；待复核/无法计算必须为 `unknown`。房间名称仍需原文证据。工具响应对原参数、边界和逐边证据设上限并标记截断；完整记录由 API 保留。

预览仍保留 80,000 展开图元上限。房间/空间查询先独立索引最多 1,000,000 个源实体，再在局部细分（每次最多 400,000 点）；房间局部裁剪、去重后最多 5,000 线段、2,000 候选面。搜索从 2 m、4 m、8 m 逐步扩展至请求上限，全部尝试范围保存在证据中。超过上限或发现未支持几何会标诊断，不把部分输入当完整净面积。候选显示最多六个；局部 SVG 背景最多 2,000 条路径，有截断提示。

当前不支持完整曲墙净边界、自动设备/柱识别、自动跨子图语义区分、多个楼层身份归并或整图房间召回率。可定位的不支持对象只影响相交的局部范围；代理对象等无法定位时仍保守阻止 `measured`，因为无法证明它们与当前局部无关。同一侧有多组实质性平行墙面时标记 `competing_parallel_wall_faces`，不再将几何双线支持等同于唯一净边。布局/图框范围仍使用工作台既有候选图框，不能视为已确认的建筑子图边界。

## 2026-10-15：自定义与 Codex harness 真实几何问题对比

结论：几何工具调用、数值计算和证据记录已经形成可用闭环；真正的模型图像输入尚未接通。四次产品运行中三次发布成功，另一次被共享的答案状态校验拒绝。当前结果不足以判定哪种 harness 总体更优，继续保留自定义 `responses_subscription` 为默认。

### 实验边界

- 样本为 `11804.dxf`，来源 DWG 为 `(6审)06-20#南区地下室人防平面图（三审）_t3_t3.dwg`；SHA-256：`4891c0757b19adb541a454e4febdecaf1e527cceb408fc22878c80ed8ce6c374`。
- 同一 GPT-6.1 Sol、low reasoning、14 个 CAD 工具、hybrid/efficient 配置、同一源快照；两个问题各跑两种 harness，一种一次，共四次。只使用订阅，没有付费 API 回退。两种运行时自身的提示与消息封装不同，正是本次比较的对象。
- 使用当前代码的冻结副本及隔离数据目录，避免正在服务的旧进程和工作区后续变化影响对比；版本为 `grounded-tools-v3.3-coverage`、`geometry-v2-scoped`、`room-net-v1.3`。未修改生产代码、重启生产服务或更换默认运行时。
- 先完成 28 项房间几何本地测试（全部通过），直接读取原 DXF 端点独立复算距离，按鞋带公式复算候选多边形面积，再进行四次真实运行。测试前预热同一进程的几何索引；耗时不含导入和预热成本。
- 问题提供选中的实体 ID 或室内点及布局，明确“本次按毫米假设”。原 DXF 单位仍未知；这不是整图自动找房间或单位识别测试。
- 实际发送图像数为 **0**。`inspect_region` 返回供用户查看的 SVG URL 并声明 `visual_input_to_model=false`；当前消息桥只接受文本和函数调用。不能将本次结果描述为视觉模型识图能力。

自定义房间题最终错误为 `SIWC_ANSWER_VALIDATION`，反馈是“第 4 条测量为程序推导；待复核测量必须标 unknown，完整测量标 derived”。失败草稿全文未保留，因此不能断言其具体哪句话错误，也不能将失败归因为算错面积。它取得证据并有限停止，但没有交付用户可用答案。三个成功答案按事前声明的 8 项检查均通过；失败题只能确认工具选择和有限停止，不能给未发布答案打完整性分。

### Harness 优先补充

1. **P0：拆分测量结论与诊断事实的契约。** 当前校验器只要 claim 引用了未完成测量，就要求整条 claim 为 `unknown`，诊断说明、记录链接和候选数据也会受影响。应区分 `geometry_observation`、`measurement_result`、`measurement_diagnostic`、`semantic_interpretation`，分别保存来源、计算完成状态和对象确认状态。候选数值可以准确转述，不能升级为已确认净面积；“工具报告存在两个阻断诊断”本身是可确认的观测。工具响应和输出 schema 应直接给出对应约束。
2. **P0：接通真正的多模态消息。** 先让一个有界工具返回可发送的 PNG 图像内容及证据元数据，再在自定义与 Codex 桥中保留图像内容，避免只转成路径字符串。先验证该订阅通道接受图像，再开展真实视觉比较；目前未验证其兼容性。官方 Responses 图像输入可用 `input_image` 承载图像，参见 [Images and vision](https://developers.openai.com/api/docs/guides/images-vision)。
3. **P1：让覆盖检查和停止条件识别几何及视觉证据。** 当前文本覆盖记录在本轮为空，订阅提前收尾逻辑的一部分依赖 `session.evidence`，不能充分反映测量观测。按“对象定位、单位依据、数值依据、语义确认、阻断项”记录覆盖；诊断不能自动解决时明确返回待确认，不继续泛搜或改参数。不要靠提高 Token 上限弥补。
4. **P1：压缩与诊断。** 工具先返回关键量、状态、支持 ID，逐边坐标按需读取；不要反复携带整个轮廓。保留脱敏的失败 claim、结构化校验原因、修复前后差异及各阶段 Token/耗时，区分“工具失败、判断不确定、答案协议失败”。纠错应针对字段，不重做已成功的几何计算。本次四轮流程均多付出了一次答案纠正。

### 视觉与几何组件优先补充

1. **P0：可读、可回定位的局部图像。** 在现有 SVG 基础上提供模型用 PNG 裁切，保留文字、线型和必要上下文；记录源 hash、layout、WCS bbox、像素尺寸、WCS↔像素变换、渲染版本及截断信息。返回全局定位缩略图和一个局部细图即可；控制分辨率和图片数。图像证据应能在界面叠加回原图。
2. **P1：候选边界的语义核对。** 用图像辅助区分墙、门窗、设备、尺寸线，结合 DXF 实体和文字标注核对竞争墙面、门洞闭合与内轮廓；保留候选及来源，不直接用模型看图估计代替精确面积。界面需要让人确认房间身份、选择边界并查看为何阻断。先解决本轮的局部歧义，不先做全图分割。
3. **P1：单位、局部完整性和不确定性。** 交叉核对尺寸标注与几何单位；将来源缺失定位到受影响范围，不能把远处不支持实体一概视为本房间缺失，也不能忽略无法定位的缺失。把几何近似误差与墙面选择/单位/身份不确定性分开显示。缓存需规范化数值参数并严格随算法版本失效：本轮 `15`/`15.0` 等等价参数已产生不同测量 ID，虽结果一致仍不利于去重。
4. **P2：扩大几何和样本覆盖。** 后续再补曲墙、复杂洞口、柱/设备扣除、尺寸与引线关联、节点图多视图对应。增加带人工确认轮廓和对象标签的小型样本集，覆盖“可确认、存在歧义、证据不足”三类；本轮只有一张平面 DXF，未验证节点图、自动导航或整图召回率。

下一步 MVP 建议先交付“局部 PNG 真正进入模型 → 图像候选绑定 DXF 实体 → 计算工具给数值 → 带原图定位的回答”这一条闭环，同时修正上述状态契约，再用少量平面/节点样本验证。无需先更换默认 harness 或扩大模型调用规模。

本次证据目录：`artifacts/siwc-subscription-20261015/geometry-harness-comparison/`。`plan.json` 保存事前问题和标准；`comparison.json` 保存逐次统计及人工检查；`verification.json`、`audit.py` 保存离线核对；各案例目录保留 `run.json` 和 `timing.json`。四次运行后账号仍已连接、活动任务为 0；离线核对没有新增模型调用。

## 通用房间识别（2026-10-15）

房间能力不以强电井、公变等 AR030 对象为定义域。AR030 批次仅为已有回归样本；识别层不导入生产规则，不按房间名称或图层白名单筛选，不需要历史房间定位点。

新增 `discover_rooms` 工具和 `POST /api/drawings/{snapshot_id}/rooms/discover`。输入为当前快照内的 `layout_id`、WCS `bbox`，可选 `frame_id` 与明确单位。界面“识别房间”分析当前视野。先通过原图线段、成对墙面和有门垛支持的闭口构建围合拓扑，再关联范围内的文字；未命名空间仍保留，不把附近文字自动认定为房间名。每个候选可定位回原图，再通过 `measurement_request` 调用现有净边界与面积工具。

输出将围合候选、墙面支持程度、房间身份、面积分别记录：`room_candidate` 表示有边界支持、未触及裁切边界且不是墙厚尺度小围合；身份始终未确认，`area_m2` 始终为空。`candidate_shell_area_m2` 只表示外壳多边形面积。细小符号、墙带及支持不足的围合保存在 `enclosure_unconfirmed` 中，界面可展开，不以任何特定房间面积阈值删除。`wall_scale_enclosure` 使用墙厚参数的一半作内缩检查，仅作尺度诊断；可能保留真实狭小空间供复核。

候选及每条边保留源图元 ID、布局、源哈希、算法版本、推断闭口和文字区域 ID。分页有独立的 `room_candidate_count` 与全部围合 `total`；二者都不是已确认房间总数。结果可通过已有测量证据 API、SVG 预览和测量记录回看；同一识别范围翻页复用同一记录。

计算有明确范围和复杂度上限（单边 200 m、5000 段、20000 次线段相交、2000 个面）。曲墙目前保留诊断、不会宣称完整识别；开放空间、设备密集区、缺失墙段和未定位代理图元仍需后续语义与图像核对。`complete` 仅表示指定范围直线拓扑计算完成，不证明房间召回完整。单位未知时不猜测。

验证包括任意名称与无名称的九个空间、旋转、带门洞、柱内环、L 形、共墙相邻空间、孤立标注框、裁切范围、曲线与复杂度上限；真实图纸另选住宅、卧室/卫生间、楼梯间所在范围。输入裁切可借助文字定位，但识别请求不接收这些名称、室内点或历史轮廓。重放脚本 `python -m scripts.validate_room_discovery`，证据目录 `artifacts/general-room-discovery-20261015/`。这些是候选发现测试，不是全类型房间正确率验收。


## 2026-10-15：局部图像闭环已接通（v3.4）

本次完成的是选定局部范围内的最小闭环：局部 PNG → 模型选择候选实体 → 几何计算 → 图片及原图定位引用。保持自定义订阅运行时默认，未加入规则策略、一次性代码执行或付费 API 回退。

### 答案状态契约

`Claim.observation_kind` 新增以下类别；旧答案未填写时使用 `auto`，仍按原严格测量契约校验。

| 类别 | 状态与约束 |
| --- | --- |
| `geometry_observation` | 已读取的几何元数据；不能用于绕过测量状态校验 |
| `measurement_result` | 完成测量用 derived/unknown；needs_review/unresolved 必须 unknown；候选面积不能升级为已确认净面积 |
| `measurement_diagnostic` | observed；仅转述状态、阻断诊断、单位依据和证据链接；不允许混入面积、距离等测量数值 |
| `visual_interpretation` | derived/unknown；必须引用本会话已发送图片的实体绑定观测，不能把模型视觉候选标为 observed |

工具返回 `claim_contract` 提示，待复核测量和诊断事实在答案中分别显示“待确认测量”“诊断观测”。这修复了以前将所有未完成测量的诊断陈述也一概要求 unknown 的问题。数值与引用检查不等于自动验证自然语言的全部工程语义，仍须保留候选及人工核查边界。

### 新工具与图像证据

- `render_region(layout_id, bbox, highlight_entity_ids=[])`：WCS 局部裁切，最长边 1024 px，最多 3000 个渲染项；PNG 最多 1.5 MB，每次问答最多两张图。返回至多 20 个带 E 编号的候选实体，可高亮至多 12 个已选图元。使用现有渲染器及 `resvg-py==0.5.0`，不是截图外部 CAD 软件。
- `bind_visual_objects(image_id, entity_ids, interpretation)`：只允许绑定本会话已发送图片中返回的候选实体。记录 ID、源快照、图片 hash、实体 ID、WCS 范围和候选解释；不自动确认构件身份。
- `measure_geometry` 和 `measure_room` 接受可选 `binding_id`。前者要求测量实体属于绑定，后者要求室内点在绑定图像范围且布局相同；保存 `visual_binding` 到测量证据。房间算法仍独立选择几何边界，视觉绑定不会强行修改或确认净边界。
- `GET /api/drawings/{sid}/images/{image_id}` 返回图像证据；追加 `/image.png` 返回经过 hash 核验的图片。记录包含源/图片 SHA-256、布局、bbox、像素尺寸、WCS↔pixel 仿射映射、渲染版本、候选截断和渲染诊断。任意路径、外部图像 URL 和跨快照引用不接受。
- 前端回答的工具观测区域提供“查看模型所见局部图并定位原图”按钮；测量边界仍通过现有测量证据按钮查看。

真实图像由父进程按会话可信记录注入自定义 Responses 请求或 Codex→SIWC 桥的请求，使用 `input_image` 的 PNG data URL；不将 Base64 交给 CLI 工具历史或保存到日志。Codex 自己的任意图片/文件请求仍不开放。最终收尾和纠错阶段继续附带同一图片。图片和图纸文字始终作为数据，不作为指令。格式依据：[OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision)。

当前只支持自定义订阅与 Codex 订阅桥；其他运行时调用图像工具会明确拒绝。旧 `inspect_region` 仍是预览链接工具，不代表模型已看到图片。几何测量观测现在也参与订阅收尾预算判断。
