# 混合检索真实 DXF 对比（2026-10-15）

已完成轻量混合检索、显式回退、网页选择和本地 BGE embedding。证据链保持原文/实体绑定。当前证据支持改善检索召回，不支持承诺端到端节省 Token 或时间。默认继续保留 keyword。

## 实验范围

四份既有真实 DXF，源文件 SHA-256 逐一复核。24 个固定问题：20 个带明确参考来源，4 个无相关原文问题。样本包含相近版本，并非四个独立项目，也没有独立业务金标或保留测试集，因此是开发性可行性实验。

检索三组使用完全相同的自然语言 query 与人工关键词，单次取前 5 个候选；Agent 端到端实验则允许模型自主选择检索词和工具，不能将单步命中率当成最终答案准确率。各组使用同一 deepseek-flash、native runtime、工具定义、提示词和预算；仅 retrieval_mode 不同。

## 检索结果

| 方法 | 原始参考命中（20 题） | 标签复核后的有效题命中（19 题） | 查询首次平均 | 查询缓存后中位数 | 无依据题返回候选 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原有关键词 | 7/20 | 7/19 | 2.2 ms | 1.5 ms | 0/4 |
| 结构分段 + BM25 | 17/20 | 17/19 | 24.5 ms | 24.1 ms | 4/4 |
| 结构分段 + BM25 + embedding | 19/20 | 19/19 | 59.8 ms | 49.0 ms | 4/4 |

标签复核发现：`59-id` 只问“DPM15”，原始金标却只指定一条 B06 墙体构造，实际上三种方法均返回了其他合法 DPM15 原文。该题不能判为检索错误，也不能证明定位到指定 B06 墙体；因此从主要命中指标排除，并保留原始 20 题统计、gold、所有候选和复核原因。没有修改原始题目或 gold 来追求更高分。

关键词排序本身贡献了主要提升。embedding 在有效正例中额外找回了两项：`61-thickness` 的“墙体厚度详建施图”，以及 `62-partition` 的地下室内分隔墙材料条款。

“无依据题返回候选”不是回答成功，也不直接是幻觉：BM25/embedding 找到了相关词或相似主题，但没有机器人电池容量依据。必须继续读取和拒绝不受支持的答案。当前未设置任意相似度阈值来掩盖这一问题。

以上查询时间不含新建 DrawingIndex、解析 DXF 或模型服务。文档索引预先构建，首查可能命中进程内重复查询缓存；缓存后时间单列，不能宣称是每次都需要全新编码的耗时。

## 答案与证据复核

- 成功回答的引用逐条检查快照、原文字符范围、实体归属及 source_parts。八次发布均通过来源检查；这不是完整语义正确率。
- 开槽问题：两组核心结论均由“严禁锤斧剔凿”支持。材料范围是否涵盖所有墙体属于推断，不能把检索命中当成材料适用范围证明。
- 表格问题：两组准确找到“200厚B06级蒸压加气混凝土砌块+两侧15厚DPM15干混砂浆”。回答仍增加了相邻钢筋混凝土做法作为“旁证”，此项与所问对象不同，不应拿来强化该砌块墙结论；这些额外陈述仍需人工核查。
- 地下室 P6：混合检索复测发布了有正确原文依据的 P6 核心答案；关键词复测实际也找到了 P6，但因两次 JSON 格式错误未发布。该差异不能归因为检索漏召回。
- 无依据问题：混合检索复测能回答“无法确定”，没有编造电池容量；首轮一次失败是混用 observation_id 和 evidence_id，证据校验按原要求拒绝发布，未为提高通过率放宽校验。
- 图纸图形与像素内容未在本次做人工逐图视觉验收，也没有新增视觉识图。

## 交付与建议

已增加网页切换、API 模式、派生向量缓存、显式回退和用量记录。原有 8765 服务未重启；8766 为本次隔离验证服务，使用本次样本数据。新前端对旧后端进行能力检查，旧后端仍发送原请求格式。正式启用可使用仓库 .venv 中的 Python 重启原服务。

当前继续保持关键词为默认；混合检索作为可选增强。下一步优化应先针对已找到相关证据后的停止条件、重复搜索和上下文体积，不宜仅通过换更大 embedding 模型来追求 Token 节约。
