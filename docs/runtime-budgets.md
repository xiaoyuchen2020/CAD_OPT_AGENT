# 订阅运行时预算与证据上下文

> 2026-10-23 更新：v2 简单做法和多图框查阅采用更小的专用预算，当前动态状态只保留一份；标准/深度预算表仍用于其他任务。详见 [v2 预算与上下文](cad-agent-execution-v2.md)。

适用于 `responses_subscription`。产品默认档为 GPT-6.1 Sol low；GPT-6.1 Sol high 为用户明确选择的深度档。未登录不自动选择付费 API，不自动升级模型，不开启批量读取。旧 API 调用者显式选择的模型/运行时保持兼容。

## 预算

| 项目 | 标准 Sol low | 深度 Sol high |
|---|---:|---:|
| 探索 token 软阈值 | 600,000 | 750,000 |
| 累计 token 请求准入上限 | 1,000,000 | 1,200,000 |
| 成稿与一次纠错预留 | 150,000 | 150,000 |
| 单次输入软阈值 / 准入上限 | 64,000 / 96,000 | 64,000 / 96,000 |
| 文字紧急上限 | 300,000 字符 | 300,000 字符 |
| 探索耗时软阈值 / 总分析期限 | 300 / 600 秒 | 420 / 900 秒 |
| 成稿时间预留 | 120 秒 | 180 秒 |
| 轮次软阈值 / 总轮次上限 | 24 / 32 | 32 / 48 |
| 工具调用上限 | 40 | 64 |
| 单次输出上限（含推理） | 8,192 | 12,288 |

软阈值后只有新的事实/来源、对象或范围绑定、覆盖与操作回执进展才能继续。无进展时收束到基于已读证据的交付，缺口仍明确保留。轮次上限包含最终成稿和一次纠错；时间不包含账号排队，包含工具与模型执行。连接超时最多 15 秒，流空闲最多 120 秒，绝对分析期限和取消同时生效。

每次实际发送及受控重试之前，检查 `已报告累计 + 未知用量预留 + 本次输入估算 + 输出上限 + 尚需保留的成稿预算`。输入以 `o200k_base` 本地分词加 20% 裕量、2,048 envelope 预留及每张图片 8,192 估算；这是订阅模型的本地估算，不冒充服务端准确计量。分词器不可用时使用 UTF-8 字节保守边界。输入本地估计与服务端计量可能不同，累计限制是请求准入控制，不是对已发生服务端用量的事后撤销保证。

已成功取得图纸信息后，若下一次探索请求无法通过累计预算准入，则记录未发送的拒绝事件并转入成稿；未发送事件不计为模型请求。成稿仍须通过自己的准入检查，不绕过累计限制。

成稿预留包含输入与输出；150,000 不是输出长度。缓存 token 也包含在总用量中，不因命中缓存而放宽累计限制。显式、未输出任何流内容的 503 `server_error` 最多重试一次；未知计费单独预留，不当作已报告用量。中断流、认证失败、配额失败、格式失败均不盲目重试。没有新增证据的相同工具和参数连续失败两次后阻止再次执行，并保留其他独立要求的执行机会；具体修复参数可以重新验证。

## 原文和几何

`analysis/evidence_store.py` 将完整来源区域、完整已请求实体的源几何、完整工具输出和错误诊断保存到本地 Store 的 `evidence_archive`。记录包含内容 SHA-256 和全部选定来源快照 SHA-256，工具消息仅携带必要摘要与 `record_id`。原始 DXF、解析区域、几何/测量记录继续保留。

模型可用 `read_evidence_record(view="catalog")` 分页找记录，用 `record_id/start/length` 读取 JSON 字符片段；单页最多 12,000 字符，`next_start` 明确后续位置。完整记录可无损重组，记录引用不等于已核对事实，目录与回读不新增证据、覆盖、对象身份或测量信用。未注册原文仍须通过 `read_source_context` 等来源工具取得合法引用。几何“完整”指保留解析器生成的全部记录，不代表曲线无离散误差或整图解析覆盖完整。

大回执摘要保留空间对象、轮廓、窗口等标识和未确认状态；后续调用入口共享最多 3,000 字符、每组最多三项，只保留参数完整的调用。`continuation_excerpt` 明确已展示数、总数和是否还有未展示项；超大单项不截断参数，改由完整档案回读。

人工检查入口：`GET /api/tasks/{task_id}/evidence-records` 返回目录；传 `record_id`、`start`、`length` 回读分页。只允许该任务已开放记录，跨任务、跨快照或内容哈希失配时拒读。现有任务/结果导出保留该目录。

## 稳定前缀与实际缓存

`runtimes/stable_prefix.py` 从任务所需工具族建立固定目录，定义顺序确定，不将每题 requirement ID 枚举写入 schema。必要工具首次开放时追加，此后不随阶段删换。阶段可调用清单放在消息尾部，并由服务端继续强制校验。最终回答保留工具 schema，但 `tool_choice=none` 且服务端拒绝调用。

历史在普通轮次追加；只有达到输入软阈值时，才将完整历史存档并生成一次有明确遗漏标记的工作上下文。完整原文/几何不靠有损摘要替代。工具结果中的大几何不反复塞回上下文，原文引用保留完整跨度。系统指令只在会话建立时构造一次。

每次请求记录 instructions/tools/prefix SHA-256、目录变更原因、输入预算估算、输出上限、实际用量和 `cache_usage`。命中数据只取服务端 `usage.input_tokens_details.cached_tokens`；缺失为 unknown，不冒充 0。汇总显示已报告请求的缓存输入比例及缺失次数。前缀相同不证明服务端命中，当前订阅通道也不据此推算美元费用或订阅剩余额度。

官方依据：[Prompt cache diagnostics](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics)。实际输出上限参数已通过 2026-10-20 的当前订阅入口短探针验证。

## 回退开关与验证

- `CAD_SUBSCRIPTION_BUDGET_POLICY=legacy`：恢复旧预算；默认 `adaptive_v1`。
- `CAD_STABLE_SUBSCRIPTION_PREFIX=0`：恢复原有动态工具曝光/上下文流程；默认 `1`。
- 批量来源读取仍由现有 `source_read_batching` 手动开启，默认关闭。
- 配置变更需要重新创建 Workspace/重启已有服务进程；已经运行的问答不被中途修改。

本轮独立回归：`tests/test_runtime_policy_v1.py`。订阅/超时/恢复集成日志：`artifacts/runtime-policy-v1-20261020/runtime-tests-final.txt`。真实模型验证分别冻结在 `artifacts/runtime-policy-v1-20261020/` 和工具目录调整后的 `artifacts/runtime-policy-v1-final-20261020/`；这是定向验收，不替代全部 20 题或三个模型的正式对照。另一并行任务继续改进 CAD 方法，故记录各自代码哈希，不将较早冻结的模型结果称为全部后续修复的验收。

最终兼容复验：`artifacts/runtime-policy-v1-20261020/compatibility-final.txt`（60 通过、2 项外部 CLI 测试按开关跳过）。包含新软预算下的有界来源补读、成稿请求预留、旧桥接流程、完整档案 HTTP 回读、视觉循环及大空间回执。验收范围、真实模型用量与引用审计、各次冻结版本差异见 `artifacts/runtime-policy-v1-20261020/acceptance-summary.json`。
