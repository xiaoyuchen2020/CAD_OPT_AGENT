# 规则库与 E0 探索底座

2026-10-29：本地开发交付。入口是 Fleet 任务中心的「规则库与探索」链接（`/rules.html`）。本阶段提供规则来源管理、冻结的单规则探索任务、授权传递和可复盘归档；真实图纸及真实模型验收待用户提供测试图纸后进行。

内置库 SHA256：`655696b873ff2003c0a7eb5dae27611273508257d47e0623b04fe3ee368d6bdd`。来源文件位于用户提供的建筑规则目录，仓库副本为 `cad_agent/rules/builtin/architecture-cn.xlsx`。打包配置包含该文件和 Fleet 静态页面，运行不依赖原用户目录。

“临时”指项目范围，文件不会在浏览器关闭后丢失，也不会自动晋升为公共库。当前 Fleet 使用共享登录密码；项目标识用于范围管理，不是不同用户之间的权限隔离。

导入状态为 `source_only` / `needs_interpretation`。原表图片会保存并展示，但没有自动解释为 RuleSpec。原文中人工判断、例外、取消步骤和无编号补充均保留，不能把成功导入理解成全部规则已经可自动执行。

## 使用

1. 启动同一版本的 Fleet 中心，登录后进入 `/rules.html`。
2. 填写项目标识。勾选内置建筑库，或上传临时 Excel，再选择本轮规则。
3. 查看原文和图片；如同编号冲突，明确停用或替换，然后点击「冻结规则集」。
4. 没有图纸时可以保存为「等待资料」。提供图纸后，基于选定规则创建带图纸的新运行；旧运行保持原冻结范围。
5. 选择 API Sol / API Astra、启动数量上限和本次要求。需要动态代码时显式勾选；原始文字明确禁止时仍关闭。
6. 保存后逐条点击「启动这一条探索」。查看运行状态、事实、方法与缺口；从详情下载归档和探索 JSON。

E0 不自动启动整库，不自动汇总成优化建议。已结束的探索不能通过普通 Fleet 重试绕过冻结范围和预算；另建一轮探索会保留原记录。运行中的瞬时网络恢复沿用同一执行编号，Fleet 自身有限重试的各次归档和用量分别保留。

## 运行配置

复用 [Fleet 部署说明](cad-fleet-deployment.md) 的中心与 Worker 配置。中心的启动入口：

```sh
.venv/bin/uvicorn cad_agent.fleet.app:create_app --factory --host 127.0.0.1 --port 8780
```

由环境提供 `CAD_FLEET_DATA_DIR`、`CAD_FLEET_TOKEN` 和登录密码或密码哈希。需要实际执行时，按部署说明启动 agent 与 Worker，配置模型及节点沙盒。

中心和节点必须使用相同源码版本；创建运行后更换事实工具、生成器、校验器或运行时文件，会得到 `EXPLORATION_TOOL_VERSION_MISMATCH`，需以新版本创建新运行。模型冻结包含 profile、provider、protocol、model 和 API 地址指纹；中心的 `CAD_GPT_API_BASE_URL` 必须与执行节点一致，地址变化会得到 `EXPLORATION_MODEL_VERSION_MISMATCH`。中心无需模型密钥即可管理规则和建立快照。快照不包含密钥或地址明文；模型供应方内部版本不受本系统冻结控制。

已有服务不会因本地文件修改自动升级。部署时需同步更新中心、agent、Worker 及静态资源；生成工件接口仅供内部令牌和匹配执行编号访问，不对浏览器代理开放。

数据在 `CAD_FLEET_DATA_DIR` 下保存：`rules/` 保存库和有效规则集，`exploration/` 保存冻结运行、case 和不可变归档；原图和执行原档仍由 Fleet 管理。备份需同时包含这些目录及节点工件存储。

## 验收语义和当前限制

- `completed` 仅表示本次 E0 执行与归档条件满足，所有 case 的 `rule_completed` 都为 `false`，业务判断状态为 `not_evaluated`。事实语义核验、完整工程对象覆盖和优化建议验证尚未实现。
- 来源缺失、工具实物缺失或损坏、交付不完整等进入 `partial`；模型失败为 `failed`；取消后迟到的证据可保留，但不能把取消升级为完成。`run.closed` 才表示整轮所有 case 已结束。
- 每 case 最多 9 张图纸、每张 32 MB；完整规则与上下文受现有 3000 字符请求上限约束。超长规则明确记录为能力缺口，绝不截断。自动拆分长规则及全图集调度属于后续阶段。
- 启动次数、并发数在派发前约束。可选 `max_reported_tokens` 只阻止后续派发；未知用量不能按零处理；它不是单次在途请求的硬 token 上限。实际模型调用仍使用现有运行时预算。
- 生成工件导出上限 8 MiB，超限显式留缺口；模型提示元数据和跨任务导入程序的旧图纸输入不导出，当前任务的执行输入和校验材料保留。API 取消在调用前后及超时边界检查，不能立即中断所有在途 socket。
- 当前没有自动公共工具晋升、规则 skill 注册、独立规则优化 Agent、管理 Agent 批量规划、金额计算和固定优化建议报告。E0 归档为后续多图纸总结提供材料。
