# 图纸概览问答失败：原因、修正与验证

日期：2026-10-14。仅修改 cad_opt_agent；没有改动 CAD 解析器、生产仓库、AR024 策略或开放代码执行。

## 现场原因

用户问题：“当前这张图纸是什么”。输入为 `真实验证-62-建筑说明.dxf`，SHA-256 为 `7710362cf2a025d101b9cea6ee9861c568c3798d9487e8429f600156a00a41e3`。

失败任务 `chat_123c189b636e4f0a9c9209aed674ec46` 在 8 轮交互中执行了 16 次工具调用，工具均成功，但模型未提交最终答案，最终返回 `AGENT_ROUND_LIMIT`。不是 API 不通，也不是引用校验拒绝。模型先后检索设计说明、工程概况、面积、目录，期间还执行了与问题无关的砌体抽取与查询。

原因有两项：工具和默认提示偏向砌体事实，没有直接提供图纸概览；循环把交互预算全部用于探索，只有已经提交错误答案时才有纠正机会，没有为未提交答案的情况保留整理阶段。“请缩小问题范围”错误地把实现问题归因给用户。

## 通用修正

- `analysis/overview.py` 从已有原文区域筛选短标题候选，返回文件元数据及最多 12 个去重标题；每个候选绑定一个原始位置、字符范围与实体。重复标题保留出现次数，但不当作图纸张数。没有原文标题时不从文件名伪造证据。
- 新增 `get_drawing_overview()` 工具，概览问题优先读取标题；砌体问题保留已有事实工具。
- 最后一轮常规交互保留用于回答，达到工具调用上限也进入回答；使用 `tool_choice=none` 在协议层关闭进一步探索。引用错误仍最多允许一次纠正，总体时间和工具执行预算维持原值。
- 提示词要求区分标题候选、目录项、实际图纸数量，不根据多个标题断言存在完整成套图纸。原文引用继续沿用既有来源绑定和点击定位。

## 证据文件与复现

本地结果目录：`artifacts/overview-fix-20261014/`。

- `before.json`：失败任务原始记录。
- `overview.json` / `query.json`：真实模型问答、工具轨迹、原文/实体/SourcePart 检查。
- `overview-budget.json`：两轮预算下的真实模型收尾验证。
- `ui-after.json` / `ui-source-checks.json`：网页任务和逐条来源检查。
- `ui-overview.png`：答案与标题实体定位截图。
- `overview-first-semantic-review.json`：首次修正后的回答。虽然来源检查通过，却把多个候选标题推成成套图纸，因此保留为反例并收紧了提示词，不作为合格语义结论。

复现当前问题：`python -m scripts.check_agent --case overview --output artifacts/overview-recheck`。该命令使用 `.env` 中的 DeepSeek 配置，将样本相关文字发送至已配置模型服务。

这是 MVP 的定向修复，不是开放问答准确率验收。标题识别是启发式候选；模型回答仍可能冗长，文件格式/布局等元数据与原图标题的引用粒度尚未完全分开。当前“这张图”指当前导入文件，没有实现跟随画布视口识别单张子图。目录项不能证明对应图纸实际存在。
