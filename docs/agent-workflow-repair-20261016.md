# 图纸问答工作流修复与回归（2026-10-16）

本次修复覆盖任务规划、单位约定、几何与局部图像核查、答案交付以及前端展示。没有按“十层/卧室”写生产分支；名称、楼层、文件路径只出现在回归样本中。

## 问题与修复

- 任务规划：把单位条件保存为约束，目标有执行步骤、依赖和交付状态。名称检索不能提前交付面积/轮廓要求，未知单位也不再中断独立几何核查。
- 单位：从用户原始提问提取明确约定，模型不能自行添加单位。条件约定会检查目标范围原生尺寸、可能的炸开数字标注及读取缺口；声明单位冲突会集中请求补充输入。
- 几何：面积/轮廓要求必须准备局部图、逐项选择或拒绝候选，再验证多边形、来源、分页名称归属和重叠。无墙图层时可以生成待视觉核查的线形候选，不依赖固定图层名称。
- 稠密图纸：几何查询逐级缩小，图像围绕候选及文字取景。单格图像不可用时保留明确缺口，不使整批失败；不可见的格子不能被选择。
- 面积：所选高亮与计算使用同一个多边形。用户确认单位后本地续作，不重新调用模型。候选围合面积不冒充净面积。
- 原图核对：所选轮廓内的面积标注单独保留原文、来源及空间关联；明确平方单位才作数值比较，单位文字不完整则提示核对。不会把图纸标注值自动覆盖几何计算值。
- 答案：单问和多问使用同一问题编号契约；未完成必要工具工作不能仅靠文字声称交付。模型选择理由中的数字不能回流成为测量证据。校验失败保留已完成分析，发布状态明确为失败，支持恢复交付。
- 上下文：仅保留必要工具集，交付阶段压缩已完成候选菜单与重复来源字段，保留选择、缺口、图片来源及测量口径。
- 前端：正文、结果表、需要补充的输入分开；日志、Token、任务步骤与证据默认折叠。表格展示数值、轮廓定位与按需证据，单位只集中询问一次。失败后也可查看已保存分析。

## 验证范围与限制

最终答案发布成功，不等于所有子目标完成，更不等于房间数量或净面积已被工程验收。D5 厨房仍缺可信独立边界。直线闭合面及有墙线支持的正交候选已有覆盖；复杂开放空间、曲墙、非正交缺口和源图代理实体缺失仍可能无法测量。

真实模型每次尝试均保留在 `live-results.json`，包含失败和修复后的重跑，没有只保留成功记录。早期失败包括工具预算耗尽、稠密图像整批失败，以及测试期间误在同一数据库启动第二个 Workspace 导致中断和后续忙碌错误。UI 验证已改为独立 `ui-data`，最终回归没有共享该测试数据库。

自动化覆盖条件单位、单位冲突、单问编号、未完成工具工作的交付拦截、页面覆盖、跨页重复空间、面积与高亮一致性、图像完整性、家具拒绝、失败恢复以及原图标注核对。最终完整测试 **615 passed、4 skipped**（2 条来自既有 Pillow 接口的弃用警告），前端 **27 passed**。最终完整日志见 `pytest-final.txt`、`node-tests.txt`；5 份真实答案再以最终契约本地复核，见 `final-contract-replay.json`。这项复核不产生新的模型调用，不替代真实推理或独立工程标注。
