# 按任务聚焦与主动交付（MVP）

本阶段只调整自定义运行时（native / responses_subscription）的工具曝光、提示、上下文和答案交付。外部 Codex / DeepSeek Harness 保持原有固定工具桥作为对照；`agent_policy=legacy` 保留原探索路径。未接入策略或任意代码执行。

## 交付检查

新增自定义运行时控制工具 `finish_analysis`，参数复用 `FinalAnswer`。模型对已读来源作语义判断并提交完整答案，服务端仍检查引用、数值、计算、测量状态、未知单位和逐项交付。通过即返回产品结果，不再请求一次模型总结。

每个未交付要求都关联了一次实际原文读取后，可进入交付检查阶段，此时只开放 `finish_analysis` 和 `request_toolset`。搜索命中、计划、工具扩展都不能充当原文阅读；长条款未读完不会仅凭截断目标进入检查。这个阶段是让模型核对是否足够，不是用阅读数量证明语义完整。

- 足以回答且检查通过：`evidence_sufficient`。
- 有明确未知/阻塞，但已交代全部要求：`partial_delivery`，任务仍可能是 `waiting_input`。
- 发现缺对象、属性、适用范围、表头、分页或冲突依据：`request_toolset` 说明具体缺口后重新查阅。
- 错误引用或漏项：不发布答案，保留校验反馈。既有时间、Token、轮数、工具预算仍生效。

每个分项最多两次显式扩展请求，只能选择注册工具组，不能启用任意函数、Shell 或文件修改。不能靠换工具覆盖未知单位。保留直接最终 JSON 回答路径，仍经过相同校验。

## 工具和提示裁剪

计划阶段仅开放 `plan_task`。执行阶段根据尚未交付要求的能力/语句选择 sources、facts、rooms、geometry、vision、semantics、components。普通文本要求默认只提供原文搜索、上下文、表格、证据和概览。名称批量房间要求默认开放批量工具；需要更广房间拓扑能力时显式扩展 rooms。

已交付、等待单位的房间分项不再让后续标题查阅携带整套测量工具。必要能力未被自动选择时，始终可通过 `request_toolset` 请求补充，不设具体项目、楼层或房间白名单。

基础文本和名称批量场景使用精简提示，保留来源、范围、例外、单位、候选状态和数值推导规则。复杂几何、视觉、语义组件，以及显式扩展的完整房间能力保留原完整说明。

## 上下文

文本复杂任务按尚未交付要求及依赖收集证据；已交付批次保留其观测和单位状态。引用原文保持原字串和字符范围，条款上下文的结构关系、前后关系、截断和分页标记保留。旧搜索轮次折叠为最近候选和简短尝试记录；完整数据仍保存在服务端任务/运行记录。

重建消息时保留最后一组完整工具调用、返回和纠错反馈，避免孤立的工具返回。只有重建确实更短才采用。视觉输入、带历史的追问及活动几何任务暂不做这类历史重建，避免丢失指代或对象绑定。该压缩不调用额外模型。

记录 `tool_count`、`tool_schema_chars`、`request_chars`、`delivery_gate` 和 `context_compactions`，用于区分预算停止和主动交付，以及核对实际输入缩减。总 Token 以模型响应的官方 usage 为准；字符数并不等于 Token 数。

## 验证

本地检查包括：搜索不能触发证据充分、批量单位阻塞不关闭独立任务、完成后不再请求总结、漏项/错误引用/未知单位面积拒绝、扩展白名单与次数限制、完整引用和条款关系保留、工具消息配对、历史和视觉保守保留。

真实验证保持前一里程碑两道问题、快照、模型、关键词检索、无回退设置不变，各提交一次。结果与来源逐项核对见 `artifacts/focused-delivery-20261016/report.md`。固定问题的小样本只说明本次流程改善，不代表所有任务的语义完整性和平均性能。

## 分页交付保护

真实验证发现批量工具曾继承搜索的 `limit=5`，导致仅交付 5/6 个名称候选后主动结束。最终实现恢复批量默认 12，并按枚举要求核对所有已读候选序号。存在 `pending_pages` 且尚有预算时拒绝提前交付，保持批量工具可用；后续页同步关联测量/高亮要求。初次展示的同图框多页高亮合并。预算确实收束时允许明确说明缺口的部分交付。该修正只进行了本地回放，没有追加真实模型调用；不得把先前的部分覆盖性能当作同等完整性的降耗结果。
