# DXF 轻量预览

主图和区域 SVG 使用 `cad_agent/cad/render.py` 的同一份 WCS 显示缓存，目标是快速查看主要内容，而非精确出图。ezdxf 1.4.3 处理文字对齐、宽度因子、旋转/镜像、MTEXT 换行、块变换、隐藏状态、DIMENSION 与 SOLID。

默认显示策略：

- 每段文字用一个 SVG text 元素，由系统字体绘制；保留 DXF 布局和测量宽度，通过 textLength 约束整段宽度。取消逐字轮廓和字形引用。字形、高度及局部字距为近似值。
- 所有线型显示为实线；屏幕线宽限制在 0.65–4px，缩小后仍可见。
- 花纹 HATCH 显示边界，实心 HATCH/SOLID 保留填充。无需生成密集花纹线。
- 超过 128 段的纯折线路径做 Douglas-Peucker 简化，容差为该路径最大边长的 0.1%；保留首尾点。普通短折线、曲线和实心面不作该简化。
- VIEWPORT/XCLIP 内文字仍走引擎轮廓裁剪，以免越界；此类内容较多的文件仍可能较重。
- `/scene` 不再传输重复的旧版线条数组；仍保留文字来源元数据供证据定位使用。

`.data/render-fonts` 或 `CAD_RENDER_FONT_DIR` 中的本地字体仅用于布局度量。已有 SHX、HZTXT/GBCBIG 字距度量保留，避免相邻文字片段重叠；浏览器采用系统字体显示。其他 Bigfont 仍为全宽回退。不存在精确字形一致性或打印精度保证。

`render.json` 是独立、可重建的版本化显示缓存；版本或本地字体变更后首次打开自动重建。原始 DXF、scene/entities/regions 索引、事实、证据及快照 ID 不迁移。布局边界变化只影响显示；显示出标注不代表语义索引已支持其全部结构。

实体数、路径数据与块递归深度均有预算；实际超限或不支持的内容会提示部分绘制。简化字体、线型、花纹属于正常预览策略，在页面提示。外部栅格图像不自动读取或上传。

## 浏览器交互优化

浏览器仅挂载当前可见区域及四周 25% 预留范围的图元，保持原绘制顺序；平移跨过预留范围或缩放变化超过约 20% 时更新。小于约 2 像素的文字在总览中暂不绘制，放大后自动恢复，原文字和语义索引不删除。长线等跨区图元仍保留。脱离视口的 DOM 节点缓存有数量上限，便于往返导航。

缩放和平移的连续输入使用 requestAnimationFrame 合并，每帧最多更新一次 SVG；拖动基于起点的屏幕位移，不在每个移动事件中读取 SVG 变换矩阵。滚轮/触控板按滚动距离连续缩放，并保留鼠标所在点。文字来源定位可以超过常规缩放范围，仍可继续缩小返回总览。显示层关闭图元命中测试，鼠标事件由画布接收；来源选择和高亮仍保留。

验证入口 `/?renderPerf=1` 只在显式启用时加载性能面板。点击按钮后，对四份 sample-59–62 图纸运行相同的逐帧缩放、总览平移、局部平移、12 次来源定位和深度缩放，结果写入页面 `render-perf-results`，不调用模型、不修改服务端数据。记录的是 rAF 帧间隔，并非 GPU 完整帧率；定位耗时包括三次 rAF 等待。结果依赖窗口尺寸和设备，前后比较应使用相同窗口。普通产品页面不会加载此面板。

## 首次打开与按需分块

页面打开 `/preview` 小清单，再加载所选布局的几何总览；文字按可靠图框分组，未识别图框的区域按 24×24 空间格分组，并按字高分档，每块最多 400 段。根据当前视口及原有显示门槛补载文字，其他布局暂不下载。分块保存原图元索引，合并和 SVG 绘制均遵循原顺序，不改变坐标、文字、线宽、颜色或填充。来源实体路径元数据在首次定位时单独加载，不阻塞总览。

分块是 `drawings/<snapshot>/preview/<revision>` 下可重建的派生缓存，清单最后原子写入；版本包括渲染版本、原渲染缓存状态及字体签名。JSON 预先压缩，避免每次请求重复解析整图和压缩响应。版本化分块允许浏览器私有缓存，清单及其他 API 仍不缓存。旧 `/scene` 和完整局部 SVG 接口保留。

浏览器最多同时请求四块；移动到新区域时优先当前视口，切图时取消旧请求，迟到的数据不会进入新图。失败时保持“当前范围加载失败”，显示重试按钮，不会把缺失分块当作完成。

`/?loadPerf=1` 是显式启用的加载验证页。它对每份图创建新的前端加载器，并用 `cache: no-store` 排除浏览器分块缓存；计时终点包括当前视口所需分块完成和绘制等待。首次分块生成与已有分块缓存的测量分开报告。它不包含应用启动或首次 DXF 导入/生成 render.json 的成本。原版与分块版的可见路径/文字指纹，以及全部分块按索引重组的内容，应完全一致。验证证据保存在 `artifacts/render-loading-20261015`。

## 高倍缩放检查

`/?highZoomPerf=1` 提供独立诊断入口，普通页面不加载该模块。四图各选短文字与长段说明两个区域，测试 1,000%、5,000%、10,000%、25,000%、50,000%、90,000% 六档，分别连续平移和缩放 96 帧。百分比与产品工具栏一致，相对于适应图纸的视图宽度；它不是屏幕实际比例。结果记录 rAF 帧间隔、超过 50/100 ms 的次数、最大挂载节点数以及分块是否仍在加载。这里的帧间隔包含浏览器调度，不等价于 GPU 帧率或纯 JavaScript 执行时间。

“高倍率瓶颈对照”在 sample-61/62 的长段说明处，以 90,000% 重复相同平移，分别保留全图、暂时隐藏文字、路径或高亮层；每种情况两轮，结束后恢复全部图层。对照仅用于定位绘制负担，不是产品显示策略。当前四图检查证据见 `artifacts/render-high-zoom-20261015`。

## 高倍率平移复用

高于约 25,000% 且缩放停止 120 ms 后，使用三倍宽高的 SVG 预留画面（每侧一个视口），按同一屏幕像素比例绘制。平移在预留范围内仅更新根 SVG 的 CSS `translate3d`，让浏览器复用合成层；超过 90% 预留边界时重新锚定。文字仍由原生 SVG 绘制，保留整段文本、字体、textLength、原变换矩阵和绘制顺序，没有分字、替换字体或缩放位图。

连续缩放期间恢复普通 viewBox 更新；切图重置预留画面，容器大小变化重新锚定。鼠标、滚轮锚点、房间测量选点均使用实际画布容器坐标，不使用放大后的 SVG 外框。分块与图元裁剪使用预留范围，避免拖动露出未绘制边缘。合成表面按 DPR 限制在约 800 万像素（RGBA 约 32 MiB）且单边不超过 8192 像素；更大窗口回到原生模式。

`/?panPerf=1` 对四图长说明区域运行 25,000%、50,000%、90,000% 三档平移，每档三轮、每轮 96 帧；前后使用相同 200 ms 稳定等待与轨迹。“核验四图显示”逐一对照原生模式与优化模式的可见图元属性、顺序与屏幕变换矩阵，涵盖普通缩放、预留范围内平移及跨边界重定位。证据在 `artifacts/render-pan-fix-20261015`。

## 不规则定位高亮

`web/highlight.mjs` 接受 DXF WCS 的 `highlight_regions: [{boundary: [[x,y], ...], holes: [...]}]`，保留凹口、洞环及不相连区域；房间测量现有的 `boundary/holes` 同样可用。旧来源按 `component_boxes`、`source_parts/parts`、总 `bbox` 依次兼容，文字估算范围不代表房间或构件真实边界。原文检索现在使用组成文字的范围，保留段落和单元格间空白。没有轮廓数据时不自动猜测工程形状。

外环和孔洞统一相反绕向，用一个 `nonzero` 复合 SVG 路径绘制，重叠填充只应用一次透明度；文字框边界仍保留，不做昂贵布尔合并。保持原绿色、透明度及屏幕线宽。按不可变来源对象 WeakMap 缓存，只有切换定位才生成路径，拖动复用既有根 SVG 合成层，不增加视图更新中的几何扫描、测量或 DOM 重建。空 `highlight_regions` 不进入旧来源的 JSON 响应。

每次高亮最多 512 个区域、16,384 个输入点，非有限/退化轮廓或超限时完整回退到原文范围并标记；不截取部分轮廓或用抽点破坏孔洞。测量层遇到回退时隐藏该轮廓并提示，不将外包矩形冒充测量边界。后台轮廓契约另检查自交和孔洞合法性；渲染层不重新计算工程几何。

`/?highlightPerf=1` 为按需加载的本地诊断页：四图各选多组件原文，比较旧矩形、组成文字范围、合成 L 形/孔洞/独立区域；25,000% 和 90,000%，两轮交错顺序，每轮 96 帧。合成轮廓只是显示测试，未写入来源/事实或宣称为真实识别结果。帧间隔包含浏览器调度，不是 GPU 帧率。证据见 `artifacts/irregular-highlight-20261015/report.html`。测试入口：`node --test tests/test_highlight.mjs tests/test_pan_buffer.mjs tests/test_viewport.mjs tests/test_preview_stream.mjs`、`python -m pytest -q tests/test_highlight.py tests/test_integration.py tests/test_room_geometry.py`。

## XCLIP 与局部 PNG 修复（2026-10-16）

渲染缓存升级至 `ezdxf-wcs-light-v7`。ezdxf 1.4.3 在 `$XCLIPFRAME=0` 时没有弹出块裁剪范围，导致后续实体、文字和布局被错误裁掉；产品前端现对每个 INSERT/MINSERT 单元使用成对的裁剪进入/退出，保留父块裁剪，并在该块裁剪退出后绘制 ATTRIB。异常退出仍恢复块属性和裁剪状态。

三份多楼层真实图的显示图元为 367,312 / 325,693 / 948,977。原 250,000 图元预算无法容纳恢复后的内容，现上限为 2,000,000 图元、240,000,000 路径字符；原有单根实体展开/递归预算和浏览器按需分块保留。上限仍可能触发，触发时明确标记部分绘制。这些大图的 JSON 缓存约 140–377 MiB，首次构建和读取会增加服务端内存与时间，不能以局部浏览顺畅推断整图构建成本。

`render_svg(..., width=..., height=..., raster=True)` 将固定输出尺寸下的屏幕线宽换算到 WCS；resvg 不执行 `non-scaling-stroke`，直接使用浏览器 SVG 会使线宽随图纸缩小而消失。交互 SVG 保持原生 vector-effect，局部图像接口改用 raster 模式，版本升为 `local-image-v2`，高亮线也按像素线宽换算。

真实图核验、前后截图、CubiCasa 同权重重跑及几何边界对照见 [渲染与识别报告](../../cad_recognition_probe_20261016/render_fix/report.html)。三张图的源 DXF 和语义索引哈希不变；全部预览分块可按索引无损重组。D1–D3 仍有 28 个 ACIS REGION 实例不支持，来自 3 个源定义；其已存顶点的变换后范围均不与试验裁剪区相交，但曲线实体的顶点范围不是严格包围盒，整图仍显示“部分绘制”。其余两张无渲染诊断，不等同于 CAD 打印级一致性认证。
