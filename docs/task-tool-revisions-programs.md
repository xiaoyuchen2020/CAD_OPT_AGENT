# 任务内工具修订与新程序

最初开发分支：`dev/task-tool-revisions-programs`。沿用 `dynamic_methods=task_verified` 或当前问题明确“允许使用动态代码”的授权；明确禁止优先。当前支持 `native` 的已配置 OpenAI 兼容 API 通道，以及 GPT-6.1 Sol 的 `responses_subscription`，沿用当前模型配置，无通道或付费回退。授权后进入 Agent 路径，避免确定性来源记录路由提前结束、使动态工具没有调用机会。2026-10-29 更新与验证边界见文末。

## 第二阶段：真实工具源码修订

`read_assembly` 的原生片段分组和阅读顺序算法已提取为 `extensions/programs/assembly_kernel.py:run`。默认读取直接调用这个纯函数；来源加载、原生行范围、标题及表头归属证明、分页与证据登记仍属于宿主。

1. 正常 `read_assembly` 取得带原生行范围的观测。
2. `inspect_tool_implementation` 返回真实源码、基础 SHA256、接口和可修改边界。
3. `revise_tool` 携带 `baseline_observation_id`、`base_sha256`、具体缺口与修改要求。模型收到原始实现，提交修改后的单模块源码。宿主保存真实 unified diff。
4. 沙箱分别运行原版、新版，并运行独立回归：当前输入、变换坐标/标识及排列的输入、三个具有微小高差的排序反例。生成器不接收回归输入或预期输出。
5. 新版必须逐个覆盖原生片段，不能截短、遗漏、重复、跨列或拼入其他正文。宿主独立核验精确栏号、y 降序、x 升序。通过后安装为当前任务、当前目标的工具版本。
6. 再次执行普通 `read_assembly`，实际通过这个版本计算片段；宿主继续原来的归属证明与证据登记。`execute_tool_version` 可在本轮另一原生行观测上重新执行并验证后安装。

这是原工具真实内核的源码替换，不是改参数，也不是另写一个旁路提取方法。当前只开放片段分组/排序内核，未开放行范围发现、工程归属规则或整个工具模块的任意修改。

当前修订契约为 `columns_exact_top_down`。原生基线保留量化行高排序；新版可修改分组实现，但必须满足完整原生片段覆盖和精确位置排序。真实 Q06 的顺序未必发生变化；排序反例用于证明算法行为确有变化，不能据此宣称 Q06 的完整做法读取质量提高。

版本路由使用 ContextVar，避免并发会话互相污染。内存算法缓存及来源记录页缓存同时加入内核版本；代码、SDK、宿主内核实现、原始 DXF 或解析工件变化都会重新验证或失效。即使命中页缓存，也先检查保存的执行输入、输出和验证记录。失败时撤销该目标路由并重新走原版，返回 `tool_version_fallback`；取消和会话超时不伪装为成功。

## 第三阶段：多模块程序和可组合结果

新增 `develop_program`、`execute_program`、`read_program_result`、`register_program`、`list_programs`。

程序包包含至多四个 Python 模块，合计 14,000 UTF-8 字节，入口为 `main.run(bundle)`。宿主只解析 AST 和构造执行载荷，不导入、编译执行生成的源码。程序及 `cad_sdk` 均在原有固定镜像、无网络、无宿主挂载、只读文件系统、非 root 容器中运行；不动态安装依赖。模块依赖与循环导入在执行前检查。

输入绑定至多四次正常工具读取的观测，可来自本轮已授权的关联图纸。宿主重新按实际读取范围构建数据，并校验 DXF、解析工件哈希和完整性。程序不能指定文件路径或自行扩大范围。需要更多数据时，Agent 先调用正常来源工具，再用新的观测调用 `execute_program`。

输出契约是最多十二个节点的有向无环图，引用必须指向前序节点；每个节点最多 1,000 行，并受字节限制。当前开放文本任务的十一种操作：

| 操作 | 含义 |
| --- | --- |
| source | 原生文字实体及精确来源 |
| select | 多关键词字面 OR 筛选 |
| field | 按首个前缀、后缀提取原文子串并更新字符范围 |
| normalize | NFKC、去空白、casefold；保留原文来源 |
| number | 解析十进制数与明确给出的字面单位，不推断单位或换算 |
| count | 指定输入集合的行数，包括经验证的零结果 |
| sum | 对相同单位的已验证数值求和 |
| compare | 比较两个有序值/单位列表是否相等，不判断材料等价 |
| join | 按值和单位相等连接，保留两侧来源 |
| sort | 值与单位的字典序排序，不冒充数值排名 |
| distinct | 按值和单位保留第一项 |

例：

```json
{
  "baseline_observation_ids": ["实际原生读取的 observation_id"],
  "instruction": "按明确契约筛选并计数，保留全部中间节点和来源。",
  "contract": {
    "nodes": [
      {"id": "source", "op": "source"},
      {"id": "selected", "op": "select", "inputs": ["source"], "keywords": ["阳台", "侧墙"]},
      {"id": "count", "op": "count", "inputs": ["selected"]}
    ],
    "output": "count"
  }
}
```

模型自行编写实现，可使用 `cad_sdk` 或自己的算法与辅助模块。程序必须输出全部中间节点、最终节点和每行来源。宿主使用与 SDK 分离的实现重放契约；值、来源、单位、节点或覆盖不一致即拒绝整个执行。未知操作或新输出类型不能由生成程序自行安装验证器，也不会获得事实证据资格。第一阶段的五种几何/表格方法继续可用；本阶段新增的是文本组合分析，尚未增加曲线/三维几何新契约或动态第三方依赖。

## 执行、证据与复用

- `develop_program` 生成并验证首次输入，首个结果直接复用该次真实执行，不重复运行。
- `execute_program` 对新输入重新执行；同一代码/输入/验证器的结果幂等读取。`read_program_result` 仅分页读结果，并重新校验来源、程序包和当前验证器。
- 程序记录、中间节点、输入、代码、执行及验证工件持久化。执行前写入状态；取消、异常或恢复遇到未完成执行时不自动重新执行或重新生成。失败节点不会产生可引用的下游结果。
- 原文引用由宿主重建精确字符范围；来源片段只证明原文，不自动获得做法归属。派生值使用宿主 `claim_templates` 并绑定相应 observation。伪造数字、宽泛工程结论、借代码哈希或数量元数据充当测量依据均不能通过答案校验。
- 算术回执来自完整契约重放；筛选回执还要求字面关键词确实出现在当前问题。回执范围始终是已绑定输入，不证明全图覆盖。
- 同一程序至少在两组不同图纸来源集合上执行验证通过，才能 `register_program` 登记为 experimental。重复同一图纸、改变分页或复制同一来源不会满足跨图门槛。
- 注册条目包含源码哈希、SDK 版本、适用契约和回归记录。跨任务显式复用只导入代码和契约，新输入必须重新执行及验证，不导入旧证据。没有自动修改公共默认工具或自动发布。

## 预算

每任务至多三个程序/修订记录，与第一阶段方法合计至多四项。每项最多三次生成，单次预留上限 32,000 token；预留、真实 usage 和未知失败费用均纳入原有总预算，保留最终回答预算。API 沿用当前问答配置；订阅沿用主问答租约，避免嵌套排队。

每次生成与验证总时限最多 180 秒，单次沙箱最多 20 秒，保留 30 秒用于任务收尾。每任务至多十二个不同程序执行结果；每个修订目标至多十六个内部输入。拒绝、取消和中断均保留账本，不能通过重试相同调用重置预算。

## 验证与证据

- `tests/test_task_programs.py`：独立契约反例、真实 diff/版本路由、缓存失效、回退、跨图执行、跨任务复用、来源完整性、答案限制和预算/取消。
- `CAD_TEST_TASK_SANDBOX=1`：同一测试包通过真实 Docker 运行，模型使用固定替身，不外发数据。
- `scripts/validate_task_programs.py --execute ...`：授权样本和真实订阅，受控生成工具补丁、新程序，真实 Docker 执行，真实模型生成最终答案，并通过正常答案验证。
- `--agent`：自然语言请求不包含工具名称，由完整 Agent 选择工具。它要求编写程序，不等于普通问答中无提示的自主补救成功率。

证据目录为 `artifacts/task-programs-20261027/`。失败尝试保留，不将通过的执行验证等同于工程语义验收或所有图纸上的质量提升。

### 2026-10-29：当前模型通道与可归档工件

方法、工具修订与多模块程序共用当前配置的生成运输层。`native` 支持 `custom`、`deepseek`、`qwen` 提供方的 `openai` 协议配置；订阅仍限定 `responses_subscription` 与 GPT-6.1 Sol。工具列表和直接执行入口共用授权及 runtime 判定，不再仅为订阅显示动态工具。原始用户授权或请求开关必须保留，任务管理者不能用派生提示代替授权；当前问题明确禁止时仍拒绝。

生成沿用本次模型、profile 和通道；失败不切换提供方，不发起付费回退。记录实际 usage、未知 usage 状态和预算预留，失败与恢复不重置额度。API 请求前后检查取消、总任务剩余时间与本次生成期限；阻塞网络调用继续由现有读取超时约束，不能保证立即取消在途 socket。迟到或取消后的提案不进入执行。订阅继续复用既有租约与运输层取消机制，沙箱隔离和独立契约重放保持原有边界。

新增内部只读接口 `GET /api/fleet-runs/{run_id}/generated-artifacts`，要求内部 Bearer token 与该运行的 `X-Fleet-Execution` 一致。它只导出绑定任务账本中允许的输入、代码、执行、验证及程序相关不可变工件，逐项核验 `ad_<kind>_<sha256>`；返回 `items`、`diagnostics` 与 `excluded`，不导出模型提示元数据或跨任务导入程序的旧生成输入。跨任务程序仍只复用代码与契约，新输入来自本任务结果。缺失、损坏或越界来源使 `complete=false`；超过 8 MiB 或 512 个唯一工件引用明确失败，不静默截断。这里的 complete 只指工件材料齐备，不代表程序正确或规则验收通过。

`tests/test_task_generation_transports.py` 使用模拟 API/订阅及模拟沙箱验证当前 Sol/Astra API 配置、订阅回归、授权门禁、无回退、用量、预算、取消和失败恢复；`tests/test_task_generated_artifacts.py` 检查内部鉴权、运行/任务绑定、允许种类、哈希、缺失损坏、跨任务程序和大小限制。本次未运行真实模型、真实图纸或真实生成代码。上方 2026-10-27 的实测数值、失败和 partial 状态保持不变，不能作为本次 API 运输路径的真实端到端验收。
