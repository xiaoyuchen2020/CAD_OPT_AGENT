## 实现

- `calculation_workflow.py`：记录可用操作数指纹。缺项检查在操作数变化后可重新调度，同一分项/运算最多三个不同输入版本；同版本不重复检查，已完成运算不再被强制调度。已执行小计作为带原始来源链的候选操作数向后续计算展示，不建立对象对应或将小计变为整套总厚度。第一版实测暴露编号2操作数被编号3遮蔽后，补上多做法共享输入、按已读构造记录分别检查、以及每个新小计的后续减法检查。候选组检查通过 review_group_id 关联，各组/操作最多两个输入版本；其他组的操作数不能用于确认本组检查。
- `delivery_recovery.py`：显式标注用户条件、引用有效且有原文依据的误标 observed 比较段，可降为 derived 后逐条重验。不会修改正文或补来源，不会保留不通过数值校验的段落。工具执行过的用户参照差值可独立恢复为条件算术记录，不代替完整总厚度和分项完成状态。
- `delivery.py`：用户标签须匹配完整数值短语才自动附着，避免把 C30 附到单纯 30mm 的运算段；对相同计算观测、相同问题分项、完整报告相同结果的重复段进行去重。互补结果、unknown/conflict 以及不同分项保留。
- `answer_protocol.py`：明确原文摘要与工具计算的不同引用协议。工具计算使用 observation_ids，不能混用 source evidence_ids 或再用内联 calculations 重新声明。
- `requirement_sources.py`：用问题中的对象、主题和字段筛选完整条件条款，避免孤立表头标签占满第一页。层数、上翻等只作为检索特征，不证明适用性；没有硬编码题号或 region_id。
- `tool_execution.py` / `focus.py`：已有初始来源后，继续扩大检索前，对明确但未读取的条件分项先读一页；每分项一次，仍受原有全局预算控制，读取后不强制枚举所有分页。
