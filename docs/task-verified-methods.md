# 任务内动态方法：第一阶段

`ChatRequest.dynamic_methods="task_verified"` 开启当前任务的动态方法；默认 `off`，旧的 `adaptation_policy_id` 旁路保持独立。网页高级选项提供“允许动态方法”。本阶段仅支持 GPT-6.1 Sol / `responses_subscription`，关闭付费回退。

也可直接在本轮问题中写“允许使用动态代码”或“现有工具不足时允许使用动态代码”，无需勾选开关。有效权限由服务端统一解析，工具列表、执行入口、来源范围记录和运行日志共用同一判定。日志 `code_execution_authorization` 区分问题明确授权、问题明确禁止和手动开关；保留原始请求字段。

仅识别当前问题中的直接授权指令，不从图纸文字、历史对话、引用或代码示例获取授权。提问“是否允许使用动态代码？”或仅提到动态代码不会开启；当前问题明确禁止时，优先于勾选开关和同轮允许表述。该授权只开放已有受控执行路径，不改变订阅、沙箱、范围、预算和验证约束。

## 调用与执行

先执行原有读取或测量工具取得 observation。`develop_method` 接收 `baseline_observation_id`、五类 `method`、`gap` 和 `instruction`。局部范围由宿主从实际工具参数或 `read_assembly` 的原生行范围绑定，不接受模型自填扩大坐标，不从“失败”描述推断授权。无真实 baseline、范围不支持、输入不完整或沙箱不可用时拒绝生成。

五类方法是 `table_grid`、`text_spans`、`segment_measurements`、`segment_distances`、`closed_contour`。模型编写独立的 `adapt(bundle)`，沿用固定 Docker 镜像、无网络/宿主挂载及资源限制。宿主独立核验来源和输出。没有改写公共工具源码、自动注册方法或任意宿主执行入口。

`develop_method` 在正常工具检查点内完成生成、执行、验证和首批结果读取。`run_task_method(method_id,offset,limit)` 重读本任务验证结果的后续页，每次重新验证工件、来源及当前验证器；它不再调用模型，也不重新执行代码。本阶段只复用同一输入的结果；换输入执行已有代码属于后续扩展。

工具调用同步等待，因此模型不会在动态步骤未完成时提交答案。任务检查点保存代码、输入、执行及验证工件。取消、异常或进程恢复不自动重复生成；未获得成功验证记录时返回未解决状态。其余子任务在工具返回后继续，尚未加入并行子任务调度。

## 字面筛选和位置排序

`text_spans` 可附加：

```json
{"text_selection":{"keywords":["阳台","设备平台","侧墙"],"order":"columns_top_down"}}
```

每个关键词必须逐字出现在当前用户问题中。仅在已有 `read_assembly` 提供原生列边界时开放该校验。宿主独立按字面 OR 计算应选完整实体，再按原生栏号、y 降序、x 升序和实体 ID 核对顺序。遗漏、额外实体、截短、重复或逆序均拒绝。只有通过时才提供 selection/ranking 操作回执；回执只证明这个局部输入上的谓词和位置排序，不证明整图完整或工程归属。

未提供这个契约时，五类原有验证器仍检查各自的原文或几何输出，但不授予筛选/排序成功回执。

## 当前回答证据

- 原文由宿主按 region/part 的精确字符偏移重新构造 evidence，只有实际返回的片段获得引用资格，未选尾文不授予读取信用。
- 新提取且未确认归属的片段，确定性结论只允许按返回的 `claim_templates` 逐字引用；语义归属保留 unknown。已有原生读取证据维持原有权限。
- 几何输出作为 derived/unknown 工具观测，保留原图单位；数值核验只读取实际测量字段，不使用哈希、坐标或数量元数据冒充测量值。
- 表格动态结果目前接入结构观测；不自动把全部表格文字登记为设计事实。
- 原文读取进入当前任务的 evidence、observation、读取进度和召回记录，最终答案仍经原有引用、数值、单位和逐项交付校验。存档本身不等于证据。
- 验证失败不登记引用资格；公共 shadow 候选不能通过 method_id 借用为当前任务结果。

本阶段不把 exact source、几何合法、代码执行成功升级成语义正确或工程身份确认。

## 预算与隔离

每任务最多两个方法/局部组合，同一组合即使改写提示也不另起生成。每方法最多三次生成或修正，单次保守预留最多 32,000 token，总计最多 96,000；每次调用同时受本轮剩余 token 和最终回答预留约束。真实 usage 与保守预留分开，未知用量的失败请求不返还预留，恢复后仍计费控额。

每方法最多 180 秒，单次沙箱最多 20 秒，并至少预留当前问答 30 秒用于收尾。来源准备完成后检查时间；解析输入本身尚不支持硬中断。生成中的网络等待和沙箱执行响应取消。主问答已有的订阅名额由内部生成复用，不嵌套申请，也不切换提供方。

## 验证

回归：`tests/test_task_methods.py`，配合适配器、表格恢复、来源读取、任务、答案校验和运行时回归。`tests/test_method_authorization.py` 覆盖本轮指令授权、禁止优先、引用与疑问句不授权，以及未勾选开关时的工具执行、证据引用和日志记录。真实 Docker 回归设置 `CAD_TEST_TASK_SANDBOX=1`，使用人工构造图纸和模拟模型，不外发数据。

`scripts/validate_task_methods.py --execute ...` 对冻结代码、明确授权的真实图纸做订阅端到端试点。该试点明确要求模型走动态方法，因此证明的是实际生成/执行/验证/本轮引用链路，不代表未提示时自主触发率或相对原生工具的质量提升。每版首次运行单独保存，失败记录不覆盖。

证据目录：`artifacts/task-methods-20261027/`。最终结果以其中的报告、冻结版本清单与对应 summary 为准。
