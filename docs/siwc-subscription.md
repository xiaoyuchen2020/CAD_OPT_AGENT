# ChatGPT 直接订阅试验

新增 `responses_subscription` 运行时和 `siwc_sol` 模型配置（GPT-6.1 Sol）。这是独立的 Sign in with ChatGPT 授权：CAD Atlas 管理 Responses 工具循环，现有 `codex_subscription` 仍由 Codex CLI 管理循环，作为对照。两个入口不共享凭据。

## 使用

启动本地服务，在问答模型中选择“GPT-6.1 Sol · ChatGPT 直接订阅”，展开“ChatGPT 直接订阅 · 独立授权”，点击 Continue with ChatGPT，再打开官方授权页面。用户在 OpenAI 页面完成账户登录和订阅使用授权后，回到产品点击“刷新授权状态”。无需将 API key 写入 `.env`。

授权独立保存在 `${CAD_AGENT_DATA_DIR}/siwc-subscription/accounts.json`（默认 `.data/siwc-subscription/`）；目录权限 0700，凭据文件 0600，原子更新。不要复制、提交或打印此文件。授权状态只返回匿名账户标签；新账户和已保存的账户授权分别处理。断开连接会清除本地令牌并尝试远程撤销；撤销失败会提示用户去 ChatGPT 设置处理。登录成功不代表目标模型权限已验证。

## 边界与接口

### 授权页 HTML / Route Error 排查（2026-10-15）

用户在官方登录页面遇到 `Route Error (400 Invalid content type: text/html; charset=UTF-8)`。排查时本地状态为未连接、没有已保存账户、仍等待回调、没有本地授权错误；真实推理尚未开始。这只能定位到授权完成前，不能单凭截图确定是浏览器会话、网络代理或官方服务故障。

官方授权文档要求使用系统浏览器。此前使用应用内浏览器，现增加“复制授权链接 · 在 Chrome / Safari 中打开”入口，并提示旧链接失效与十分钟有效期。点击复制会先检查本地授权是否仍在等待；结束后清除页面链接。新入口已在浏览器验证复制成功，JavaScript 语法检查通过。当前 Chrome 自动控制未获授权，交由用户手动粘贴新链接；这不是登录成功验证。

请在系统浏览器完成登录和独立订阅授权，回到 CAD Atlas 刷新状态。若仍出现相同错误，保留错误文字及发生步骤即可，不分享包含 code/state 的完整网址、Cookie 或令牌。不自动改走 Codex 凭据、其他授权端点或付费 API。

- 本机单用户、单进程 MVP。只接受环回地址及受校验的 Origin/Host；OAuth 回调使用临时环回监听器，不记录回调查询参数。
- OAuth 使用独立动态客户端、PKCE S256、state、nonce，并校验 ID token 签名、签发者、受众、有效期和身份。订阅权限以 token 响应的 scope 为准。续期使用本应用自己的 refresh token。
- `GET /api/siwc-account`：脱敏状态。`POST /api/siwc-account/login`：新授权；可带已有 `account_id`。`POST /api/siwc-account/logout`：断开当前授权。`GET /api/siwc-account/models`：授权后的模型目录读取，不运行推理。
- 默认问答请求使用 `runtime=responses_subscription`、`model_profile=siwc_sol`、`allow_fallback=false`。现另支持通过 API 将该订阅配置与 `deepseek_harness` / `codex` 桥接运行时组合（见末尾实测）；不支持与 `native` / `codex_subscription` 混用，任何订阅回退组合都在推理前拒绝。网页默认选择逻辑未变。
- 模型通过公开 `https://api.openai.com/v1/responses` 接口调用；`store=false`、流式响应、显式传递历史及加密 reasoning 项。仅提供 `cad` 命名空间下的现有九个只读工具，不开放代码执行或托管工具。
- 复用原图证据、引用校验、重复调用缓存和探索控制。找到证据且累计 Token 达到 30,000、探索达到 40,000 或时间接近上限时，下一轮仅整理最终答案；最后一轮禁止工具调用。50,000 是软目标，不是服务端硬额度：单次响应可能超过它。
- 必须收到成功的 `response.completed` 才处理结果；中断、配额或鉴权失败不发布部分答案，不自动重试，不调用付费 API。回答校验失败最多追加一轮无工具的整理，计入总轮数预算。
- 保存官方逐请求 usage、耗时和状态；订阅 Token 记录不等于账户额度百分比，也不是 API 美元费用。失败流没有 usage 时不推测其实际消耗。

### 响应格式排查与修复

在用户额外明确允许一次简短探测后，使用相同订阅和 GPT-6.1 Sol 发送一次 `Reply exactly: OK`，不带 DXF、没有工具、不重试。结果为 HTTP 200，**缺少 Content-Type 响应头**；读取了 6,066 字节，正文前缀呈 SSE 格式，未截断。旧检查因此在解析事件之前拒绝响应。这证明当前直连路径存在缺少类型头的响应，解释了同类错误的触发机制；之前 DXF 那次未保存响应头，不能追溯证明两次响应完全一致，也不能判断响应头由哪个服务或中间层省略。

未授权、不进行推理的公开路由检查分别得到 OPTIONS 405 / JSON、GET 401 / JSON；这两项检查没有出现 HTML，但不能排除仅作用于订阅 POST 的网络差异。诊断记录仅保存响应形状、认可的错误代码及参数、请求 ID，不保留原始正文、令牌或 Cookie。

已修复适配器：媒体类型按规范忽略大小写；缺少 Content-Type 时尝试严格解析 SSE，必须有有效 Responses 事件、`response.completed`、完成状态和相同模型才放行。HTML、普通 JSON、错误事件、流中断和模型不匹配仍然失败；显式返回其他媒体类型也不当作成功。工具白名单、引用校验及禁止付费回退保持不变。

修复后完整本地测试 **205 项通过**，覆盖缺少类型头的工具调用、调用结果配对、引用、用量及上述失败情形。8766 服务已加载修复。额外探测仅一次，耗时 2.646 秒，未记录 usage，实际 Token 未知；该排查回合没有因修复而重新运行探测或真实 DXF。之后另获用户授权的真实验证见下节。

### 停止逻辑修复（本地验证）

仅修改直接订阅的 `ResponsesSubscriptionRuntime`，保留原 Codex 运行时及共享引用校验。首次成功调用图纸工具前使用 `tool_choice=required`；成功调用后回到 `auto`。模型仍未调用工具就作答时，不再把这类错误当作答案格式问题直接收尾。
